# Test Design: `ui-prototype/src/main.rs`

Source: `ui-prototype/src/main.rs`

Source-SHA256: `242bdb00099f5829b033ca374c74deac98babd39b24f63e73c88c68c25d1db1c`

## Test Strategy

`main.rs` contains no workspace logic. The replies it applies come from the kernel handler, whose cases are in `ui-prototype/tests/it_slice_a.rs` (TC-620 to TC-645). The labels, status texts, availability texts, section texts and diff totals it shows come from `ui-prototype/src/model.rs` (TC-601 to TC-615). The build lanes are TC-600.

The window is checked by eleven manual system tests (TC-650 to TC-660, ST-GUI-01 to ST-GUI-11) on Windows 11 with `ladon-gui.exe` built by `cargo build --release --bin ladon-gui`. Each step is performed by hand, and each case names its checkpoints, where a screenshot is taken. A case passes when every expectation at every checkpoint is met. A case fails when any expectation is not met. Slint callbacks have no automated test in this release.

Each window case names, in its Input / Setup cell, the kernel and model tests whose behaviour it depends on, using the exact identifiers. Kernel identifiers are `ui-prototype/tests/it_slice_a.rs::it_6xx_...` and model identifiers are `ui-prototype/src/model.rs::ut_6xx_...`.

The requirements covered are REQ-003 (listing large folders, TC-660), REQ-009 (version history and diffs, TC-657 and TC-658), REQ-063 (keyboard operation, TC-651 and TC-655), REQ-064 (zoom and light display, TC-659), NFR-002 (every command shows a visible result, in every case), NFR-003 (browse, record, history and diff work offline, TC-652 to TC-658), NFR-004 (sensitive content is not sent outside the machine, TC-657), NFR-007 (actor and reason are shown for every version, TC-657), NFR-013 (path safety for traversal, links, reparse points and device names, TC-652 to TC-654 and TC-660), NFR-014 (keyboard, focus and contrast, TC-655 and TC-659), NFR-015 (Simplified Chinese messages, TC-659), NFR-017 (messages do not expose content, TC-660) and NFR-026 (keyboard operation and 100, 125 and 150 % scaling, TC-655 and TC-659).

Fixtures are created under `C:\ladon-test\`, which is neither the drive root nor the user profile directory. Symbolic links are created as junctions with `mklink /J`, which needs no elevation. The fixture `C:\ladon-test\ws` is an initialised workspace with this content:

- the folder `docs` with the files `one.txt` and `two.txt`;
- the file `a.txt`;
- the junction `link` to `C:\ladon-test\outside`, created with `mklink /J link C:\ladon-test\outside`.

Its root listing is `docs`, `.LADONignore`, `a.txt`, `link`, in that order, with `.ladon` omitted. The later cases add files to this root and state the rows they expect.

Every case starts with the application closed, unless its precondition says otherwise.

## Boundary & Failure Cases

- A command that is not sent because another command is in flight shows 正在处理，请稍候。 and sends nothing. The buttons are disabled in that state, so the case is reached from the list keys (TC-660, step e).
- A reply that arrives after the window has closed is dropped without a message (TC-660, step f).
- The banner 后台服务已停止，请关闭并重新打开应用。 cannot be produced by a user action. It is set only when `Worker::send` returns false. `ui-prototype/tests/it_slice_a.rs::it_643_send_reports_stopped_worker` covers the worker side, and no system case shows the banner.
- The note 差异计算超过 2 秒，结果可能不是最小改动。 appears only when a diff call reaches its 2-second timeout. No manual step reaches the timeout, so no system case shows the note.
- Refused and invalid paths show only the fixed messages, without path content, file content or a stack trace (TC-660, steps a to c).
- A version whose content is not local stays comparable. Its card shows the availability text 内容不在本地，暂不可比较. Pressing 与上一版比较 on the card above it, which is the next version, shows 该版本的内容不在本地，暂不能比较。 (TC-658, `cold.txt`).
- Link rows and other entries show no record button (TC-654 and TC-660, step d).
- A folder with more than 5000 entries shows 5000 rows and the count 共 5000 项; the list shows no separate notice (TC-660, step e).
- Chinese names of files, folders and diff lines show complete glyphs at every scaling (TC-659).

## Regression Scope

- `app.rs`: every reply shape and command rule used by this module, covered by `ui-prototype/tests/it_slice_a.rs::it_620_init_open_and_needs_init` to `it_645_constants_and_message_text`. The window cases TC-650 and TC-652 to TC-660 exercise these replies and command rules.
- `model.rs`: the row text, status text, availability text, section text, version rows and diff totals shown in the window, covered by `ui-prototype/src/model.rs::ut_601_format_bytes` to `ut_615_diff_lines_limits`. The window cases TC-654, TC-656, TC-657 and TC-658 show these texts.
- `ui/app.slint`: layout, palette, keyboard order and overlays. The window cases TC-651, TC-655 and TC-659 check these, each with the screenshots named at its checkpoints.
