# Test Design: `ui-prototype/src/main.rs`

Source: `ui-prototype/src/main.rs`

Source-SHA256: `5640d75856a0eb3e67ba7d5c1aa241ab0cac0b2a60efca532b99cfefcc681b68`

## Test Strategy

`main.rs` contains no workspace logic. The replies it applies come from the kernel handler, whose cases are in `ui-prototype/tests/it_slice_a.rs` (TC-620 to TC-653). The labels, status texts, availability texts, section texts and diff totals it shows come from `ui-prototype/src/model.rs` (TC-601 to TC-615). The build lanes are TC-600.

The window is checked by twenty-nine manual system tests (TC-700 to TC-728, ST-GUI-01 to ST-GUI-29) on Windows 11 with `ladon-gui.exe` built by `cargo build --release --bin ladon-gui`. Each step is performed by hand, and each case names its checkpoints, where a screenshot is taken. A case passes when every expectation at every checkpoint is met. A case fails when any expectation is not met. Slint callbacks have no automated test in this release.

Each window case names, in its Input / Setup cell, the kernel and model tests whose behaviour it depends on, using the exact identifiers. Kernel identifiers are `ui-prototype/tests/it_slice_a.rs::it_6xx_...` and model identifiers are `ui-prototype/src/model.rs::ut_6xx_...`.

The requirements covered are REQ-003 (listing large folders, TC-710), REQ-009 (version history and diffs, TC-707 and TC-708), REQ-063 (keyboard operation, TC-701 and TC-705), REQ-064 (zoom and light display, TC-709), NFR-002 (every command shows a visible result, in every case), NFR-003 (browse, record, history and diff work offline, TC-702 to TC-708), NFR-004 (sensitive content is not sent outside the machine, TC-707), NFR-007 (actor and reason are shown for every version, TC-707), NFR-013 (path safety for traversal, links, reparse points and device names, TC-702 to TC-704 and TC-710), NFR-014 (keyboard, focus and contrast, TC-705 and TC-709), NFR-015 (Simplified Chinese messages, TC-709), NFR-017 (messages do not expose content, TC-710) and NFR-026 (keyboard operation and 100, 125 and 150 % scaling, TC-705 and TC-709).

Fixtures live on three test volumes with their own drive letters, `X:\`, `Y:\` and `Z:\` (mounted virtual disks or USB volumes, not `subst` drives), and under `C:\ladon-test\` for the folder that the junction points to. Symbolic links are created as junctions with `mklink /J`, which needs no elevation. The drive root `X:\` is an initialised workspace with this content:

- the folder `docs` with the files `one.txt` and `two.txt`;
- the file `a.txt`;
- the junction `link` to `C:\ladon-test\outside`, created with `mklink /J link C:\ladon-test\outside`.

Its root listing is `docs`, `.LADONignore`, `a.txt`, `link`, in that order, with `.ladon` omitted. The later cases add files to this root and state the rows they expect.

Every case starts with the application closed, unless its precondition says otherwise.

## Boundary & Failure Cases

- A command that is not sent because another command is in flight shows 正在处理，请稍候。 and sends nothing. The buttons are disabled in that state, so the case is reached from the list keys (TC-710, step d).
- A reply that arrives after the window has closed is dropped without a message (TC-710, step e).
- The banner 后台服务已停止，请关闭并重新打开应用。 cannot be produced by a user action. It is set only when `Worker::send` returns false. `ui-prototype/tests/it_slice_a.rs::it_643_send_reports_stopped_worker` covers the worker side, and no system case shows the banner.
- The note 差异计算超过 2 秒，结果可能不是最小改动。 appears only when a diff call reaches its 2-second timeout. No manual step reaches the timeout, so no system case shows the note.
- Refused and invalid paths show only the fixed messages, without path content, file content or a stack trace (TC-710, step a).
- A version whose content is not local stays comparable. Its card shows the availability text 内容不在本地，暂不可比较. Pressing 与上一版比较 on the card above it, which is the next version, shows 该版本的内容不在本地，暂不能比较。 (TC-708, `cold.txt`).
- Link rows and other entries show no record button (TC-704 and TC-710, step b).
- A folder with more than 5000 entries shows 5000 rows and the count 共 5000 项; the list shows no separate notice (TC-710, step c).
- Chinese names of files, folders and diff lines show complete glyphs at every scaling (TC-709).
- A silent refresh never sends while a command is in flight, so the timer never shows the busy text (TC-712).
- A silent refresh never sets `busy`, so no busy indicator or disabled button appears between refresh cycles (TC-714).
- A failed silent refresh keeps the rows that were shown and sets the failure status (TC-713).
- The GUI runs as a Windows GUI program, so launching it opens no console window; the command-line program keeps its console (TC-715).
- A silent refresh whose selected row is gone clears the selection without a message; `selection_after_refresh` returns `None` in that case (TC-617).
- An uninitialised drive root is initialised and opened by a double-click (TC-702). A drive root that cannot be initialised keeps the This PC page and shows the drive message (TC-703).
