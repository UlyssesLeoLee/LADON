# Test Design: `ui-prototype/src/app.rs`

Source: `ui-prototype/src/app.rs`

Source-SHA256: `9883ad2ddb7152cac3f1d56c5ac95a67be7572b87e5140fde8bf06178edaff9a`

## Test Strategy

- Location: `ui-prototype/tests/it_slice_a.rs`. Kernel lane: `cargo test --no-default-features --features kernel`. The window build `cargo build --release --bin ladon-gui` compiles this module through `main.rs`.
- Each case that works on a folder creates its own `tempfile::tempdir()`, uses the canonical path of that directory as the workspace, and calls `app::handle` on a `State::new()` inside a `#[tokio::test]`; the worker cases (TC-642, TC-643) use `Worker::spawn` instead. Assertions use the returned `Reply`, the files on disk and the ledger, read through `ladon_explorer::store::Store` and `ladon_explorer::archive::CasStore`. No mocks are used: the kernel's Turso database, content store and rule loading run against the temporary directory.
- The worker cases (TC-642, TC-643) use `Worker::spawn` with `std::sync::mpsc` channels. Their waits are bounded: 60 seconds for replies, 5 seconds for the stop check.
- Links in the tests are directory junctions created with `cmd /C mklink /J`, which needs no elevation (TC-624, TC-638), and file symbolic links created with `cmd /C mklink` (TC-624), which needs the privilege SeCreateSymbolicLinkPrivilege (Developer Mode or an elevated shell). When that privilege is missing the case fails with a message that names it; it is never skipped. A failure to create any link fails the test. The link cases (TC-624, TC-638), the exclusive-handle case (TC-641) and the drive-list case (TC-646) are compiled for Windows only.
- An exclusive open with share mode `0` makes the kernel's read of the file fail (TC-641). Rule-file change detection is exercised by moving the modification time with `File::set_modified` (TC-640).
- Requirement traceability:
  - REQ-003: a folder with more than `LIST_LIMIT` rows stays bounded (TC-627).
  - REQ-009: version history and text diff of recorded versions (TC-628, TC-630 to TC-636).
  - REQ-063 and REQ-064, NFR-014 and NFR-026 concern the window. They are verified by the manual cases ST-GUI-01 to ST-GUI-11 outside this lane.
  - NFR-002: every command has a visible result, shown by one reply per command (TC-642) and by fixed failure messages (TC-641, TC-645).
  - NFR-003: every case runs offline against local storage only.
  - NFR-004: the diff and history cases read local content only and never reach a provider (TC-632 to TC-635).
  - NFR-007: actor and reason are shown for every version (TC-628).
  - NFR-013: path safety for traversal, links, reparse points and device names (TC-623, TC-624, TC-626, TC-637 to TC-639).
  - NFR-015: only Simplified Chinese messages exist; TC-645 compares the exact texts.
  - NFR-017: messages and logs do not expose content; failure replies carry fixed messages and no detail (TC-641, TC-644, TC-645).

## Boundary & Failure Cases

- Refused and invalid paths never reach the kernel or the disk: TC-637 and TC-639 check that nothing is created or recorded.
- A junction in any ancestor of a root candidate, a directory junction at `.ladon` or `.ladon/cas` under it, or a file symbolic link at `.ladon/meta.turso` or `.LADONignore` under it, is refused without any write through it (TC-624). A drive root is accepted as a candidate, and the user profile directory is refused (TC-623). An internal directory name as a component of a root candidate is refused (TC-623).
- Exactly at the diff limit the diff is computed; one byte over it is refused (TC-634). `LIST_LIMIT` truncates the folder listing (TC-627). `DIFF_MAX_LINES` truncates the diff (TC-631).
- A zero byte makes a version binary wherever it occurs in its content (TC-632). A zero byte takes precedence over invalid UTF-8 (TC-633).
- A failed Open keeps the open workspace in place (TC-640). A capture that fails records nothing (TC-639, TC-640, TC-641).
- A ledger row marked deleted is invisible to history and to tracking in the listing (TC-629).
- A file given as the folder fails the listing with InvalidPath (TC-626).
- A panic inside the callback stops the worker thread, and later sends return false (TC-643). A panic inside a command becomes an internal failure reply (TC-644).
- Rules verified by code review only, because no deterministic fixture exists:
  - the containment check after canonicalisation, which follows the link checks that TC-638 covers;
  - the `Other` entry kind, which the walk cannot produce from fixtures;
  - entry names that are not valid Unicode;
  - I/O failures during the root candidate checks;
  - the `TooLarge` reply after loading, which applies when a loaded content is longer than `DIFF_LIMIT_BYTES` while its recorded size is not;
  - the `Kernel` reply with `MSG_DIFF_FAILED` for a failed version lookup in LoadDiff, and the `Kernel` reply with `MSG_CAPTURE_FAILED` for a failed version-number read after capture;
  - the internal failure reply for every command when the runtime cannot be built.

## Regression Scope

- Kernel paths exercised by this module: `engine.rs` (`init`, `open`, `capture`, `reload_policy`, `load_version`), `store.rs` (`find_path`, `list_files`, `version`, `versions`, `events`, `verify_chain`, `mark_deleted`), `archive.rs` (`CasStore::has` and `evict`) and `policy.rs` (rule loading and parse errors).
- The kernel test files `tests/it_engine.rs`, `tests/it_store.rs`, `tests/it_policy.rs` and `tests/it_history.rs` are kernel tests; the cases of this module are in `tests/it_slice_a.rs`.
- The model lane (`ui-prototype/src/model.rs` unit tests, `cargo test --lib --no-default-features`) is the test lane of the functions this module depends on: `check_component`, `validate_relative`, `browse_rows`, `version_rows`, `diff_lines`, `strip_extended_prefix`, `drive_rows` and `same_directory`.
