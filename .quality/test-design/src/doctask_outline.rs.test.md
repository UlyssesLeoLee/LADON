## Test Strategy

The tests are unit tests in the `tests` module of `src/doctask_outline.rs`. They use no database, file system or clock. Each equality with `diff::section_hashes` is checked on the same bytes and the same lowercase extension, comparing the list of keys and the full hashes pairwise. Expected body hashes are computed in the test as the SHA-256 of the body lines, each followed by a newline, and expected row hashes as the SHA-256 of the row text followed by a newline. Golden values are not stored; the expected values are derived from the input text in each test. Test bodies in the anchor cases are written with more than 40 non-whitespace characters and at least two non-blank lines unless a case states otherwise.

Verification runs in a project outside the repository (channel B of the work breakdown): a temporary crate that includes `src/doctask_outline.rs`, `src/doctask_model.rs`, `src/diff.rs`, `src/crypto.rs` and `src/nema.rs` through `#[path]` attributes, with the lightweight dependencies of `doctask_model`. The temporary crate has no `store` or `engine` module. The tests of `src/diff.rs` (`ut_diff_01` to `ut_diff_03`) run in the same project and must pass unchanged.

## Boundary & Failure Cases

- Headings: `#` alone (not a heading), `#` followed by a space and no title (heading with empty title), six and seven hash characters, a heading at the first byte of the buffer, and a heading that is the last line without a newline.
- Clause tokens: `A-1` (accepted), `a1-2b` (rejected), `REQ-101-5` (rejected), `REQ-101:` (accepted), digits only (rejected).
- Rows: a table row whose first cell is empty; a row without a closing `|`; a list item whose first word is a number without a dash.
- Body metrics: a body with only blank lines has `body_lines` 0 and `body_chars` 0; whitespace of any kind is excluded from `body_chars`.
- Splice: a range that ends at the end of the buffer with and without a final newline; an insertion into an empty buffer; a byte-order mark alone (three bytes) as the whole buffer; `new_text` ending with `\n` at the end of a buffer without final newline.
- Lossy outline: a buffer that is not valid UTF-8 is outlined without error (the same keys as `diff.rs`), and the splice functions reject it.

## Regression Scope

`doctask_service`, `doctask_reconcile`, `doctask_plan` and `doctask_report` depend on the keys, numbers, ordinals, fingerprints, error codes and splice bytes of this module. A change to a key rule, a hash input, the dominant-newline rule or an error code changes stored anchors and must fail TC-840, TC-844 or TC-847 before any other module is changed. The `diff` module is used read-only: `ut_diff_01`, `ut_diff_02` and `ut_diff_03` must keep passing, and `src/diff.rs` must not change.
