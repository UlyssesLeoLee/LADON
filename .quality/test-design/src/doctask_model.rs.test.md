## Test Strategy

The tests are unit tests in the `tests` module of `src/doctask_model.rs`. They use no database, file system or clock. The matrix tests compare every combination with an independent literal table written in the test, not with the function's own table. The hash tests compare against golden digests computed outside the crate with the SHA-256 of the same JSON text (compact separators, non-ASCII kept as UTF-8). Each golden test also changes every field in turn and asserts that the digest changes.

Verification runs in a project outside the repository (channel B of the work breakdown): a temporary crate that includes `src/doctask_model.rs` and `src/nema.rs` through `#[path]` attributes, with dependencies `serde`, `serde_json`, `anyhow` and `sha2` at the versions of the repository lock file. The temporary crate has no `store` or `engine` module, so a successful build proves the module does not depend on them. Tests run with `cargo test -j 1` and an isolated target directory.

## Boundary & Failure Cases

- Handles: `0`, `-3`, the empty string, a leading and trailing space (trimmed and accepted), `t-12` (rejected by the uppercase prefix rule), eight-character hexadecimal prefixes with and without a letter, the UUID with uppercase digits.
- Text: exactly 200 and 201 characters for titles; exactly 4000 and 4001 characters for descriptions; exactly 500 and 501 characters for reasons and plan summaries; `new_text` at 262144 and 262145 bytes; target file at 1 MiB and 1 MiB plus one byte; a UTF-8 byte order mark followed by valid text; a carriage return that is not followed by a newline.
- Transitions: every pair of states with no row returns `E_TRANSITION_DENIED`, including identical states and `done` to `cancelled`.
- Scheduling: an empty input gives empty output; a single task with no target goes to `unknown_targets`; a dependency chain of three layers gives three batches; a task whose only dependency is done is in the first batch.
- Chain: a record whose stored hash is altered but whose `prev_hash` link is intact is reported at its own `seq`.

## Regression Scope

`doctask_store`, `doctask_flow`, `doctask_service`, `doctask_outline`, `doctask_render`, `doctask_report` and the command modules depend on the types, codes and hash encodings of this module. Changing a stored string, an error code, an exit code, a limit, a tuple order or a golden digest changes persisted chains and must fail the tests above before any other module is changed. The `nema` module is used read-only here; its `topo_batches` tests (`ut_nema_01_graph`, `ut_nema_02_parallel`) must keep passing.
