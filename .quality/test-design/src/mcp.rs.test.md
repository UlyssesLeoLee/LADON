## Test Strategy

The tests are unit tests in the `tests` module of `src/mcp.rs`. The functions named by document 41 are `ut_155_handshake_version_negotiation` and `ut_156_notifications_ping_bad_lines`. `ut_155_handshake_version_negotiation` calls the case functions `tc940_supported_versions_echoed`, `tc941_unknown_or_missing_version` and `tc942_initialize_result_shape`. `ut_156_notifications_ping_bad_lines` calls `tc943_notifications_and_client_replies_silent`, `tc944_ping_list_and_call_routing`, `tc945_unknown_method_echoes_id`, `tc946_bad_json_and_invalid_requests`, `tc947_invalid_utf8_line`, `tc948_bounded_reading_and_eof` and `tc949_fixture_lines_parse_and_replay`.

The fixtures are built in the test module. `RecordingHost` implements `ToolHost`: `tools()` returns a fixed list, `call()` records `(name, arguments)` in `calls` and returns `reply.clone()` for the name `probe_echo` and `None` for any other name. Requests are fed to `Server::handle_line` as byte slices, and whole inputs to `Server::serve` through `std::io::Cursor` readers and `Vec<u8>` writers. The helper `run_serve(server, bytes)` runs `serve` on a `Vec<u8>` output, splits it at `\n` and parses each piece with `serde_json::from_str`; it fails the test when a piece is not one JSON object. The helper `reply_of(server, line)` returns the `handle_line` result for a literal string, `error_parts(reply)` returns the code and message of an error reply, `read_all(bytes, max)` runs `read_bounded_line` until `Eof`, and `classify_all(text)` runs `parse_line` on every non-empty line of a fixture. The reader `Flaky` reports `Interrupted` once before its data.

The golden fixtures are read with `include_str!("../tests/fixtures/mcp_client/<name>.jsonl")`, so a missing fixture fails the build. The tests do not read the environment, the clock, the file system beyond these fixtures, or any database.

## Acceptance Traceability

| Acceptance item (WBS 58, WP12) | TC | Input | Assertion |
| --- | --- | --- | --- |
| Negotiation of 2025-11-25, 2025-06-18, 2025-03-26 and 2024-11-05 | TC-940 | Four supported versions | Each version echoed |
| An unknown version answers 2025-11-25 | TC-941 | Future, empty, near-miss and wrong-type versions | Fallback to 2025-11-25; missing version is -32602 |
| The golden lines are parsed by the protocol layer | TC-949 | `hermes_mcp_test.jsonl`, `sdk_session.jsonl` and both reply files | Every line classified; replay produces the expected replies |
| Notifications get no reply | TC-943 | Notifications, blank lines, stray client replies | `handle_line` returns `None`; no host call |
| `ping` returns `{}` | TC-944 | `ping` with numeric and string ids | `result` `{}` |
| An unknown method gives -32601 and echoes the id by type | TC-945 | Numeric, string, null, zero and empty ids | `-32601`; id kept with its type |
| Bad JSON gives an error reply and the loop continues | TC-946 | Truncated, non-JSON, deeply nested and non-object lines | `-32700` or `-32600`, id `null` or echoed; next line answered |
| Invalid UTF-8 gives an error reply and the loop continues | TC-947 | Bytes `\xff` and `\xc3\x28` | `-32700`; next line answered |
| An oversized line gives an error reply and the loop continues | TC-948 | `MAX_LINE_BYTES + 1` bytes, followed by a ping | One `-32600` reply; ping answered; the exact limit is accepted |
| EOF ends the loop | TC-948 | Empty input | `serve` returns `Ok(())` with no output |
| Every output line is exactly one JSON object | TC-946, TC-948, TC-949 | Serve runs over bad, oversized and golden inputs | Each output line parses as one object; no raw newline inside a reply |
| Module-level `deny` of stdout macros | Not covered by these tests | Clippy run | Reported as not verified until a clippy channel exists (WBS 5.1); IT-062 and IT-067 guard stdout |

## Boundary & Failure Cases

- Line length: exactly `max` bytes is accepted; `max` plus one is `Oversized`; the same at the real 4 MiB limit (TC-948 h).
- Lines without a newline at end of input: a non-empty last line is returned; an oversized last line is `Oversized`; an empty input is `Eof`.
- Blank lines: empty, spaces and a carriage return are ignored silently; a line of `\n` alone is ignored.
- JSON depth: 200 nested arrays give `-32700`, because `serde_json` stops at its recursion limit (TC-946).
- Identifiers: number, string, `null`, `0`, the empty string, a boolean and an array. Only the last two are invalid.
- `jsonrpc`: missing, `"1.0"` and `2.0` as a number. Missing or wrong values on a request are `-32600`; on a notification they are silent.
- `params`: absent, `null`, an array, a scalar and an object. Non-object `params` are treated as absent, so `initialize` reports `protocolVersion is required` and `tools/call` reports `name is required`.
- `arguments`: absent and `null` become `{}`; any other value reaches the host unchanged (TC-944).
- Interrupted reads are retried (TC-948 g). Other read errors and write errors end `serve` with `Err`.

## Regression Scope

`doctask_mcp` (WP13) and `tests/it_mcp_stdio.rs` depend on the reply shapes, the messages and codes in the regression paragraph of `mcp.rs.md`, the `ToolHost` method signatures and the `ServerInfo` fields. Changing any of them must fail TC-940, TC-941, TC-942, TC-944 or TC-949 before a caller is changed. The fixture replay in TC-949 fails when the golden files change shape.
