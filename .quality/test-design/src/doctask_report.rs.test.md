## Test Strategy

The tests are unit tests in the `tests` module of `src/doctask_report.rs`. The functions named by document 41 are `ut_153_nema_roundtrip` and `ut_154_report_determinism`. `ut_153_nema_roundtrip` calls the case functions `tc920_nema_roundtrip_and_batches`, `tc921_nema_label_sanitising`, `tc922_node_token_rules` and `tc923_dependency_errors`; `ut_154_report_determinism` calls `tc924_repeat_export_identical`, `tc925_cutoff_ignores_export_event`, `tc926_local_only_omitted`, `tc927_gated_file_omitted`, `tc928_rollback_chain_and_restore_command` and `tc929_chain_check_and_empty_chain`.

Fixtures are built in the test module from literal `TaskRecord`, `PlanRecord`, `ApprovalRecord`, `EvidenceRecord` and `EventRecord` values and the report records. The helper `base_input()` builds two files, one clause, two tasks with one dependency and two links; `full_input()` extends it with an annotation, a plan with its stat, an approval, an evidence row, two versions, a commit and five events. The helper `chain(specs)` numbers events from 1 and links them with `computed_hash`, so the chain is intact unless a case corrupts it; `chain_event` builds one export event on a given previous hash. A small helper `is_node_row` tells node rows from the header and edge rows of the NEMA text. No file, database, clock or environment variable is used.

Verification runs in a project outside the repository (channel B of the work breakdown): a temporary crate that includes `src/nema.rs`, `src/doctask_model.rs` and `src/doctask_report.rs` through `#[path]` attributes, declaring `serde` 1 with the derive feature, `serde_json` 1, `anyhow` 1 and `sha2` 0.10, with its own target directory. The source-text check of TC-924 searches the module for the forbidden paths `crate::store`, `crate::engine`, `crate::doctask_store`, `crate::doctask_service` and `crate::doctask_render`; the paths are written with `concat!` so that the test text itself does not contain them.

## Boundary & Failure Cases

- NEMA: a title longer than 80 characters is cut to 80; an empty title gives `-`; a title made of controls and bidirectional characters is replaced by `<U+XXXX>` markers; a task without a clause produces no `Traces` edge.
- Tokens: an id whose filtered form has exactly 8 characters; an id that is not a UUID but has hexadecimal digits (`1f-2e_3d:4c`); a UUID with hyphens (the hyphens are dropped); two ids whose first 8 and 12 characters agree and whose first 16 differ (lengthened to 16); two ids identical after filtering; an id without a hexadecimal digit.
- Dependencies: a cycle returns `E_DEP_CYCLE`; a dangling prerequisite and a hidden prerequisite are omitted and counted; a visible prerequisite outside the scope is listed and not counted, and no edge is written for it.
- Scope: `Task` of an absent id and of a hidden id; `File` of an absent id and of a gated file; `All` with records that have no clause.
- Chain: an intact chain; a tampered payload (first break at the tampered `seq`); an empty chain; a chain that contains only an export event.
- Markdown: `|`, `#`, `<`, `>` and `*` in annotation text and inline text are escaped; an annotation with several lines is printed as one blockquote line per input line; a carriage return is normalised.
- JSON: the output of every export parses back with `serde_json::from_str`; `restore_command` is null when there is no earlier version.

## Regression Scope

The command layer (`doctask_cli`, WP11) and any screen that shows report text depend on the section order, the header line keys, the `ladon.doctask.report.v1` schema name, the NEMA domain headers and the edge labels (`Traces`, `Refines`, `Implements`, `VerifiedBy`, `Targets`, `Blocks`). Changing any of them must fail TC-920, TC-924 or TC-928 before a caller is changed. Adding a field to a JSON row is allowed; removing or renaming one is not.
