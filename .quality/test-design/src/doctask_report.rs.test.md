## Test Strategy

The tests are unit tests in the `tests` module of `src/doctask_report.rs`. The functions named by document 41 are `ut_153_nema_roundtrip` and `ut_154_report_determinism`. `ut_153_nema_roundtrip` calls the case functions `tc920_nema_roundtrip_and_batches`, `tc921_nema_label_sanitising`, `tc922_node_token_rules` and `tc923_dependency_errors`; `ut_154_report_determinism` calls `tc924_repeat_export_identical`, `tc925_cutoff_ignores_export_event`, `tc926_local_only_omitted`, `tc927_gated_file_omitted`, `tc928_rollback_chain_and_restore_command` and `tc929_chain_check_and_empty_chain`.

Fixtures are built in the test module from literal `TaskRecord`, `PlanRecord`, `ApprovalRecord`, `EvidenceRecord`, `EventRecord` and the report records, with a helper `chain(events)` that computes each `hash` with `event_hash` so that the chain is intact unless a case corrupts it. No file, database, clock or environment variable is used.

Verification runs in a project outside the repository (channel B of the work breakdown): a temporary crate that includes `src/doctask_model.rs`, `src/nema.rs` and `src/doctask_report.rs` through `#[path]` attributes, declaring `serde` 1 with the derive feature, `serde_json` 1, `anyhow` 1 and `sha2` 0.10, with its own target directory. The source-text check of TC-924 searches the module for the forbidden paths `crate::store`, `crate::engine`, `crate::doctask_store`, `crate::doctask_service` and `crate::doctask_render`.

## Boundary & Failure Cases

- NEMA: a task title of exactly 80 characters and of 81 characters; an empty label; a label holding only a tab; a task with no clause and no link; a file with no edges; zero tasks (header-only text); an edge whose target file is sensitive (omitted).
- Tokens: an id of exactly 8 filtered characters; an id with fewer than 8 filtered characters (the full filtered id is used); two ids identical after filtering; a UUID with hyphens (hyphens dropped, 8 characters kept).
- Dependencies: a self-dependency in the input (`T-1 -> T-1`) returns `E_DEP_CYCLE`; duplicate dependency pairs produce distinct edge ids and no error; dangling prerequisites are omitted and counted; a visible prerequisite outside the scope is listed and not counted.
- Scope: `Task` of an absent id and of a hidden id; `File` of an absent id; `File` with a section that matches no clause (the report shows no clause, no error); `All` with no records (every section `（无）`).
- Chain: a broken `prev_hash` in the first event (reported as `seq` of the first event); events with gaps in `seq` (checked by `prev_hash` only); two `dt.export.generated` events, one before and one after the cutoff.
- Markdown: a title that starts with `#`, a path containing `|`, a backtick and a `[link](x)` string, an annotation with three lines and a carriage return; each appears escaped and as one blockquote line per input line.
- JSON: a string with a quote, a backslash and U+202E; the output parses with `serde_json::from_str` back to a `Value`.
- Timestamps: `generated_at` empty and containing a bidirectional control, sanitised in the header.

## Regression Scope

The command layer (`doctask_cli`, WP11) and any screen that shows report text depend on the section order, the header line keys, the `ladon.doctask.report.v1` schema name, the NEMA domain headers and the edge labels (`Traces`, `Refines`, `Implements`, `VerifiedBy`, `Targets`, `Blocks`). Changing any of them must fail TC-920, TC-924 or TC-928 before a caller is changed. Adding a field to a JSON row is allowed; removing or renaming one is not.
