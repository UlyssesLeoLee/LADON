## Test Strategy

The tests are unit tests in the `tests` module of `src/doctask_render.rs`. They use no database, file system, clock or environment variable. The screen tests compare the whole output with a literal golden text written in the test, line by line, so that alignment of mixed Chinese and English columns is checked by character position and not by the function's own width arithmetic. The width tests use literal expected widths derived from the East Asian ranges of the design. The catalogue tests read both catalogues and the `ALL` arrays of the model, so a missing or extra key fails the build of the tests.

Verification runs in a project outside the repository (channel B of the work breakdown): a temporary crate that includes `src/doctask_model.rs`, `src/nema.rs` and `src/doctask_render.rs` through `#[path]` attributes, with the dependencies `serde`, `serde_json`, `anyhow` and `sha2` at the versions of the repository lock file. The temporary crate has no `store` or `engine` module, so a successful build proves the module does not depend on them. Tests run with `cargo test -j 1` and an isolated target directory.

## Acceptance Traceability

| Acceptance item | TC | Input | Assertion |
| --- | --- | --- | --- |
| Mixed Chinese and English columns align (UT-151) | TC-910, TC-911 | Wide and narrow characters; tab and newline in cells; short and long rows | Display widths literal; every column starts at the same display column; no trailing spaces |
| CJK display width and table alignment (UT-151) | TC-910, TC-911 | Ranges U+1100 to U+FFE6 listed in the design | Widths 2 inside the ranges, 1 outside |
| Screens match golden text (UT-152) | TC-915, TC-916, TC-917 | Fixed sample screens in both languages | Whole output equals the golden lines |
| Chinese and English catalogues have identical key sets (UT-152) | TC-912 | Both catalogues and enumeration `ALL` arrays | Equal sorted key lists; named slots equal; every enumeration value present |
| Plain-text mode has no ANSI (UT-152) | TC-918 | Every renderer in `Plain` mode with hostile text | No escape character in the output |
| Every error code has Chinese and English message and hint (UT-152) | TC-913, TC-914 | `ErrorCode::ALL` in both languages | 54 keys per language, each non-empty; rendered lines carry the texts |
| Control and bidirectional characters rendered as visible markers (UT-145) | TC-914, TC-918, TC-919 | ESC, U+202E, U+200B, tab and newline in details and cells | Replaced by `<U+XXXX>`, tab and newline by a space |
| Trace screen contains annotations, downstream tasks, links, Agent changes and commits, test evidence and rollback chain | TC-916 | Full sample trace | Each section present in order with its item line; rollback command present |
| Approval screen shows short expected and result hashes, and the baseline check on its own line | TC-917 | Approval sample with `Differs` and `NoBaseline` | Twelve-character hashes; baseline line separate from the hashes; prompt names the task |

## Boundary & Failure Cases

- Width: the empty string, a single wide character at a padding boundary (`文` to 3), U+1F600 outside the ranges, the first and last code points of every listed range.
- Table: zero rows, zero headers, a row with fewer and with more cells than headers, a cell with a tab, a newline and a carriage return (the carriage return is shown as `<U+000D>`).
- Outline: zero rows; a baseline with an approver name containing a bidirectional control; the first and last clause lines equal.
- Trace: each section empty; a section with several items; a task without a plan and without dependencies; a task with a plan and two dependencies.
- Approval: exactly five options (all shown) and six options (only the first five shown); empty diff; a diff line that begins with ESC; an empty other-plan list; a hash of exactly 12 and of 13 characters.
- Errors: empty `message_zh` and `hint_zh` fall back to the catalogue in `Zh`; a detail of `""` produces no detail line; every code renders in both languages with non-empty lines.
- Lang: `EN`, `zh-CN` and the empty string are not accepted.

## Regression Scope

`doctask_cli`, `doctask_mcp` and `console` take their screen and error text from this module. Changing a catalogue key, a line template, a column order, a golden line, a width range or the painter sequences changes the output the owner sees in acceptance tests ST-077, ST-078, ST-081, ST-082 and ST-088, and must fail the tests above before any caller is changed. Adding an error code or an enumeration value to the model requires its catalogue keys in both languages; TC-912 and TC-913 fail until they exist. The model's `sanitize_display` is used read-only here; its tests (TC-837) must keep passing.
