# Test Design: `src/engine.rs`

Source: `src/engine.rs`

Source-SHA256: `cdda1887b240b0214bbec6f22bef77c7e4c596eb69836cf3e658ddc0323f09ba`

## Test Strategy

Integration tests use a real `Engine` over a `tempfile::tempdir` workspace, a real Turso database, the real CAS and a `FilesystemProvider` pointed at a temporary directory (in `tests/it_history.rs`, the `remote` subdirectory of the workspace temporary directory). There are no mocks. The ledger and live-tree tests live in `tests/it_engine.rs`, which also holds TC-314, TC-315, TC-316, TC-318, TC-321, TC-324, TC-326, TC-327 and TC-328. That file assumes the environment variable `LADON_GLOBAL_IGNORE` is unset, because the policy reads it, and its tests run in parallel. TC-314, TC-318 and TC-326 are the tests in the file that call `archive_version`; each is refused before the archive key is read (TC-314 and TC-318 by the sensitivity check, TC-326 by the policy reload check). TC-318 sets `LADON_ARCHIVE_KEY_HEX` to the virtual test key for the file's process; the refusal happens before the key is read, so the value does not change the outcome, and no other test in the file reads the variable. Archive upload and load tests need the same variable; they live in their own file `tests/it_engine_archive.rs` as a single sequential test, so tests that depend on whether the variable is set cannot race with other tests (each integration test file is its own process). The key used is a fixed 64-hex-digit virtual test value, never a documented example key. The `tests/it_history.rs` cases also exercise the engine. The inline unit tests in `src/engine.rs` (TC-319, TC-320, TC-322, TC-323, TC-325, TC-329 to TC-333, and the two background-traversal tests of TC-859) run inside the module. `restore_with_hook` takes four seams: `before_backup` (TC-319), `before_place` (TC-332), `before_capture` (TC-322, TC-329, TC-330, TC-331) and `before_rollback_removal` (TC-329). TC-320 calls the private `scan_walk` with a walk rooted at a missing directory, which yields a real walk error. A test is Pass when its exact name is listed as passing in the final test run or in an earlier recorded run named in docs/04_tests/46; every other case, including one covered only by a file-level count and one with no test function, is Not Run.

The external transfer gate (`remote_read_allowed`, `remote_version_allowed`, `refresh_policy_if_stale`, `rule_traversals`) is tested in `tests/it_engine_gate.rs` (IT-054, TC-850 to TC-857). That file holds one process-wide lock, because each test sets or removes `LADON_GLOBAL_IGNORE`; every test takes the lock and runs its async steps on a current-thread runtime built inside the locked scope. The 30-second nested interval cannot be waited for in an integration test, so the background traversal is tested inside `src/engine.rs` (TC-859), which sets the last traversal time back directly and waits for the background traversal to finish before the next call. Rule-file edits in the gate tests that must keep the same size and modification time set the modification time explicitly. The gate cases TC-850 to TC-857 and TC-859, and the policy tests of TC-858 (listed in `policy.rs.test.md`), passed in the run recorded in `docs/04_tests/46` section 1.7.

## Boundary & Failure Cases

- Open checks only the global and root rule files synchronously, so an invalid nested rule file does not stop open. The background scan started by open reads nested rule files, and its error is returned to captures (TC-315, which checks the open result and the capture outcomes).
- An invalid root rule file makes open fail and return no engine (TC-316). A missing root rule file also makes open fail; no test covers that refusal, and TC-326 covers the refusals of reload_policy, capture and archive_version for a root rule file removed while the engine is open.
- A capture under a failed rule scan fails and records nothing; after `reload_policy` with a valid rule file, the next capture succeeds (TC-315). Scan returning the rule-scan error from its first capture is not covered by a test; TC-315 exercises capture only.
- A failed rule scan makes `archive_version` return the scan error before the archive key is read or any object is uploaded (TC-317).
- Unchanged content returns status unchanged and creates no version (it_history it_01).
- A file larger than 8 MiB switches to the large-file marker (TC-310).
- Eviction followed by capture exercises the cold-previous branch (TC-311).
- Eviction never happens before the remote object authenticates (TC-311).
- Restore must never overwrite a live file whose hash differs from the ledger (TC-304).
- Restore of a deleted file works without a live target (TC-305).
- A live file that changes between the digest check and the move aside is put back, and the restore records nothing (TC-319). A failed put-back of the moved-aside backup is not covered by a test; the error names the backup path.
- A failed capture after a restore keeps a live edit: the target is moved aside, and the moved-aside file is removed only when it holds the restored bytes, with the pre-restore file moved back from the backup; otherwise the target and any backup are kept and the error names them (TC-322). A target that cannot be read is kept in the same way; no test covers that case.
- A failed move back of the aside file during rollback is not covered by a test; the call then fails with `live file changed during rollback and could not be put back`, naming the aside path, in place of the capture error.
- A restore whose placement finds a file already at the target keeps that file and the backup, and records nothing (TC-332). Copy-based placement never replaces an existing file (TC-333).
- A successful restore whose backup cannot be removed returns the restored result; the backup stays in `.ladon/restore` and no error is reported (TC-331, Windows only).
- Live-file and backup digests are computed in 64 KiB chunks and equal the digest of the whole file (TC-323).
- `relative_for_input` accepts a plain absolute path under the root that the canonical root does not prefix (TC-321), and the absolute path of a tracked file that was deleted (TC-327).
- Internal paths (`.ladon`, `.git`) and outside-workspace paths cannot be captured (TC-306).
- A missing or malformed archive key stops archiving before any upload (TC-311).
- A version is never archived when its content hash was also held by a sensitive version or by a path that the current rules exclude, including deleted and moved paths (TC-314, TC-318, TC-324).
- A path that contains a `..` component is refused by `remote_path_allowed` (TC-1044).
- A directory walk error fails the scan before any deletion is recorded (TC-320).
- A file that cannot be captured does not stop the scan: the other files are captured, the deletion pass runs, and the scan returns an error that names the file (TC-328, Windows only). A rule set that did not load stops the scan with its error before the first capture; no test covers that path.
- A copy of excluded content at a path that the rules do not cover is excluded by its hash, because a path that has held the same hash is excluded by the current rules (TC-324).
- `tag-folder` judges a tracked file by its ledger hash; a file overwritten with excluded bytes but not yet captured is judged by its old hash, and no test covers that case.
- `normalise_relative` drops empty components, including a leading `/`, and keeps `..` components. TC-325 covers `.`, doubled separators and backslashes; the leading `/` and `..` cases have no test.
- Known limitation without a test: `scan` does not capture the root `.LADONignore`, so a ledger entry for that file is marked deleted by the first full scan after it is tracked, and later scans skip it.
- Known limitation without a test: `ledger_path` checks the whole canonical path, so a workspace under a folder named `.ladon` or `.git` refuses every capture.
- Known limitation without a test: `relative_for_input` fails with the I/O error of `canonicalize` when the parent directory of an absolute path no longer exists.
- Known limitation without a test: a failed rollback rename of the target to the aside file reports that the live file no longer holds the restored bytes.

- Every refusal of the remote gates is `Ok(false)`: an invalid root or global rule file, a failed rule load, a sensitive flag, an excluded path and an excluded content hash each refuse (TC-851, TC-852, TC-853). The exceptions are a store error and a poisoned policy lock, which return an `Err` that callers treat as a refusal.
- The gates never trust a stored flag alone: a file whose stored flag is clear is still refused when its path or its content is excluded now (TC-850, TC-852).
- A rule edit that keeps the same length and modification time is seen through the content digest of the stamp (TC-857).
- A policy marked invalid is rechecked on every call, so the gate reopens when a broken root or global rule file is restored with the stamp it had before the break. No test covers that restoration; TC-853 restores each broken state through a changed stamp.
- A consecutive run of gate calls with unchanged rules starts no traversal, and the nested interval makes a background traversal start at most once in 30 seconds (TC-856, TC-859).
- A background traversal that fails installs a failed rule set, so transfers stay refused until a later traversal loads (TC-859).

## Regression Scope

The engine writes every ledger record through `store.rs`. `agent_api.rs` calls `resolve` in `read_file_local`, `relative_for_input` and `content_is_excluded` in `allow_remote_read`, and `file_by_path` in `history`, while `list_folder` calls `store.find_path` directly; `tests/it_store.rs` and `tests/it_agent_folder.rs` must stay green, and so must `tests/it_engine_gate.rs` and the inline tests of TC-858 and TC-859. `archive_version` reaches `Store::paths_for_hash` through `content_is_excluded`, which is covered through TC-314, TC-318, TC-324 and the remote-read case TC-410 in `tests/it_agent_folder.rs`. The CLI commands `capture`, `scan`, `archive`, `plan`, `restore` and `diff` call these methods, with `diff` going through `load_version`. The CLI record lookup `resolve_record` in `src/entry.rs` calls `relative_for_input` for absolute input (TC-321, TC-327) and `normalise_relative` for relative input (TC-325). The `tag-folder` command in `src/entry.rs` (`tag_folder`) calls `content_is_excluded` after its path check; TC-324 calls that function directly. Its skip (`skipped remote AI tagging for excluded file`) is covered by `src/entry.rs::tag_folder_skips_excluded_files_for_remote_endpoint`, which excludes its file by path, so the content-hash branch has no test. `src/doctask_service.rs` (`EngineGate`) implements the transfer gate on top of `refresh_policy_if_stale`, `remote_read_allowed` and `remote_version_allowed`, and treats an `Err` from either decision as a refusal (`unwrap_or(false)`). The deferred rule scan that `Engine` waits on is covered by `tests/it_policy_pending.rs` (TC-514 to TC-517). The policy, CAS and crypto modules are otherwise exercised indirectly and have their own inline tests.
