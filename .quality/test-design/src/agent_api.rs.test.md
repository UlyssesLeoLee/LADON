# Test Design: `src/agent_api.rs`

Source: `src/agent_api.rs`

Source-SHA256: `01f7bb7974e9e6113ccc3d10dec1983a14fc69a3e1a8e228fb95579007d7708f`

## Test Strategy

Integration tests build a real `Engine` over a `tempfile::tempdir` and call `AgentApi` methods directly, with no mocks. Files are created with `std::fs`; tracked files are captured through the engine so that ledger references exist. The link test creates a real symbolic link and, on Windows, a directory junction through `mklink /J`, which needs no special privilege; when neither can be created the test skips its assertions, unless the environment variable `LADON_REQUIRE_LINK_TESTS` is set, in which case it fails. The listing-order test uses the names `B.md` and `a.md`, whose bytewise order differs from their case-insensitive order. A missing sort is detected unless the host already enumerates the three entries in bytewise order (`B.md`, `a.md`, the subdirectory); NTFS, which enumerates `a.md` before `B.md`, is one host where it is detected. The host's enumeration order is not asserted. No test sets process-wide environment variables. The `it_agent_folder_snapshot_history` test and the inline `ut_agent_capability_status` test cover the basic folder, history and capability paths. `allow_remote_read` is async, and TC-407 and TC-410 await it. The directory junction of TC-410 is created on Windows only; when no junction can be created, the alias case is skipped with a message, unless the environment variable `LADON_REQUIRE_LINK_TESTS` is set, in which case the test fails. The grep skip rules of `grep_local` are covered at the `search::grep` level in `src/search.rs` (TC-409), and the rule collection behind the rule set in force, which `allow_remote_read` consults through `Engine::remote_path_allowed`, is covered by the `src/policy.rs` unit tests of `LadonPolicy::load` and of `walk_entry`, the walk helper that `LadonPolicy::load` applies to each step, which are listed with their execution status under Regression Scope.

## Boundary & Failure Cases

- Limits exactly 1 and 1000 are accepted, 0 and 1001 are rejected (TC-402).
- Read limit exactly 8 MiB is accepted and 8 MiB plus one byte is rejected (TC-405).
- A folder outside the workspace given as an absolute path is denied with the containment error, and a parent reference never lists anything (TC-403); an absolute file path outside the workspace is denied for reads (TC-405).
- Symbolic links and junctions are skipped, never followed (TC-404).
- Tracked and untracked entries in the same folder are distinguished by the ledger reference (TC-401).
- Names are sorted bytewise, so `B.md` precedes `a.md` (TC-401); the host's enumeration order is not asserted.
- Files that cannot be read (locked, missing, not UTF-8) are skipped by grep_local instead of failing the search (TC-409).
- Rule-collection cases of `allow_remote_read` (a lower-case root rule file name, nested rule files at depth 2 or deeper, negation scoped to its directory, walk errors) are not asserted by the `AgentApi` tests. They are asserted in the `src/policy.rs` unit tests `ut_policy_lowercase_rule_file_is_applied` (Pass), `ut_policy_nested_negation_stays_in_its_dir` (Pass) and `ut_policy_nested_anchored_negation_stays_in_its_dir` (Pass), which call `LadonPolicy::load`, and `ut_policy_walk_error_fails_closed` (Pass), which calls `walk_entry`, the helper that `LadonPolicy::load` applies to every walk step.
- A tracked copy of excluded content, and a directory alias of excluded content, are refused by `allow_remote_read` (TC-410). A root rule file removed while the engine stays open fails the call with the refresh error (TC-411). A copy that has not been captured is not refused, because the content check reads the ledger (known limitation, no test).
- `history` maps backslashes only; a path with a `./` prefix, a doubled separator, a `.` component, a different letter case or an absolute form is not found even when tracked (known limitation, no test).
- A workspace under a folder named `.git` or `.ladon` makes `grep_local` skip every file, so the search returns no hits without an error (known limitation, no test).

## Regression Scope

`engine.rs` (resolve, relative_for_input, content_is_excluded, file_by_path, store access), `archive.rs` (`assert_under_workspace`, called by `resolve`), `store.rs` (find_path, versions, verify_chain), `policy.rs` (`LadonPolicy::load` and `allow_external`, behind the rule set in force that `allow_remote_read` consults; unit tests `ut_policy_lowercase_rule_file_is_applied` (Pass), `ut_policy_nested_negation_stays_in_its_dir` (Pass), `ut_policy_nested_anchored_negation_stays_in_its_dir` (Pass) and `ut_policy_walk_error_fails_closed` (Pass), and `tests/it_policy.rs` TC-505 to TC-512) and `search.rs` (`search::grep`, behind `grep_local`) feed this module. The `agent-list` CLI command uses `list_folder`. `tests/it_history.rs`, `tests/it_store.rs` and `tests/it_engine.rs` must stay green.
