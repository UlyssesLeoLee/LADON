## Test Strategy

The tests are of two kinds. Unit tests in the `tests` module of `src/doctask_store.rs` cover the pure helpers (anchor key parsing, legacy payload rule, chain-conflict and lock-error classification, identifier and table checks) and the retry bounds of the write driver, by calling it with scripted closures; they need no database. Integration tests in `tests/it_doctask_store.rs` use a real temporary turso file created through `Store::new`, `Store::ensure_schema(false)` and the legacy `Store` API to build fixtures, then drive `DocStore`. Raw SQL through a separate `turso::Builder` connection is used only to simulate the cases the API must reject or detect (tampering, deletion, a stale counter, an old binary changing a status without writing an event, a duplicate `prev_hash`, an anchor whose file is missing). Concurrency is exercised with two `DocStore` values on the same file polled together by `tokio::join!`; assertions are on the outcome (one winner, intact chain, every write present), not on timing.

Expected digests and payload texts are compared with values computed in the test from `doctask_model::sha256_hex` of the literal input, so a change to the hash helper or to the payload construction fails the tests.

Verification runs in the CI job `release.yml` (`cargo test --locked --all-targets` on `windows-latest`), with the local gnullvm check as the first channel when memory allows.

## Boundary & Failure Cases

- Counter values at 0 and at the first allocation (row absent) and the first increment (row present).
- `transition` with an empty `task_id`: the lookup finds no row and returns `E_NOT_FOUND`.
- `transition` with `from_status` equal to `to_status`: accepted as a CAS only when the stored status equals it; the record is appended with both fields equal.
- `append_event` and `transition` with an empty `kind` or a `payload_json` that is not JSON: `E_INVALID_ARG`, nothing written (`tests/it_doctask_store.rs::it_049_invalid_inputs_are_rejected_before_any_write`).
- `create_task` with priority 0 and 4: `E_INVALID_ARG` from `validate_priority` before any statement runs (same test).
- `create_task` with an anchor belonging to another file: `E_INVALID_ARG`; `add_annotation` with such an anchor: `E_INVALID_ARG`; with an unknown anchor: `E_NOT_FOUND`; with a file missing from `resources`: `E_NOT_FOUND` (same test). A second `ensure_anchor` for the same triple returns the existing id.
- `backfill` on an empty library: all report fields zero, one counter row created (`it_050_backfill_on_empty_library_reports_zero_and_counts_runs`).
- `legacy_payload` with an empty payload for `task.state_changed`: hashed (the empty string is not a state).
- Lock exhaustion: after six lock errors the write returns `StoreBusy`, whose text begins with `E_STORE_BUSY`. The write driver is exercised directly by the unit test `tc864_retry_policy_bounds`; the store's own UT-162 covers the open path.
- `insert_row` with a value list that names a column that does not exist: the statement fails, the transaction rolls back, and the error is returned unchanged (`it_049_generic_writer_rejects_unknown_columns_and_writes_nothing`).

## Flow Primitives

The step primitive `commit_step`, the row writes `UpdateWhere` and `Delete`, and the readers `plans`, `approvals`, `evidence`, `links` and `anchor_reviews` are exercised through the flow; the readers `anchors` and `lineage` and the `current_hash` set on creation are exercised by the reconciliation tests TC-900 to TC-909 in `tests/it_doctask_reconcile.rs` in `tests/it_doctask_flow.rs`: a failed compare-and-set, a failing row write and a duplicate identifier roll the whole step back (TC-882); the chain order of evidence and approvals decides the acceptance rule (TC-885); the delete of a dependency row and the update of several plan rows are checked by TC-895 and TC-890. The anchor review columns are read by the anchor guard of TC-892.

## Regression Scope

`doctask_service`, `doctask_flow` and `doctask_reconcile` (WP06 to WP08) call these methods and depend on the event hash tuple, the payload shapes, the legacy payload rule and the counter names; changing any of them changes persisted chains and must fail TC-862, TC-867 to TC-869 before any other module is changed. `Store` and `Engine` are used read-only by these tests: the tests in `tests/it_store.rs`, `tests/it_doctask_migration.rs` (IT-047, IT-073 and the probe tests) and `tests/it_engine.rs` must keep passing unchanged. The pure model tests (UT-141 to UT-146) must keep passing because the hashes come from `doctask_model`.
