## Test Strategy

The tests are of two kinds. Unit tests in the `tests` module of `src/doctask_store.rs` cover the pure helpers (anchor key parsing, legacy payload rule, chain-conflict and lock-error classification, identifier and table checks) and need no database. Integration tests in `tests/it_doctask_store.rs` use a real temporary turso file created through `Store::new`, `Store::ensure_schema(false)` and the legacy `Store` API to build fixtures, then drive `DocStore`. Raw SQL through a separate `turso::Builder` connection is used only to simulate the cases the API must reject or detect (tampering, deletion, a stale counter, an old binary changing a status without writing an event, a duplicate `prev_hash`). Concurrency is exercised with two `DocStore` values on the same file polled together by `tokio::join!`; assertions are on the outcome (one winner, intact chain, every write present), not on timing.

Expected digests and payload texts are compared with values computed in the test from `doctask_model::sha256_hex` of the literal input, so a change to the hash helper or to the payload construction fails the tests.

Verification runs in the CI job `release.yml` (`cargo test --locked --all-targets` on `windows-latest`), with the local gnullvm check as the first channel when memory allows.

## Boundary & Failure Cases

- Counter values at 0 and at the first allocation (row absent) and the first increment (row present).
- `transition` with an empty `task_id`: the lookup finds no row and returns `E_NOT_FOUND`.
- `transition` with `from_status` equal to `to_status`: accepted as a CAS only when the stored status equals it; the record is appended with both fields equal.
- `append_event` with an empty `kind` or a `payload_json` that is not JSON: `E_INVALID_ARG`, nothing written.
- `create_task` with priority 0 and 4: `E_INVALID_ARG` from `validate_priority` before any statement runs.
- `create_task` with an anchor belonging to another file: `E_INVALID_ARG`; with a missing file: `E_NOT_FOUND`.
- `backfill` on an empty library: all report fields zero, one counter row created.
- `legacy_payload` with an empty payload for `task.state_changed`: hashed (the empty string is not a state).
- Lock exhaustion: after six lock errors the write returns `StoreBusy`, whose text begins with `E_STORE_BUSY`. This path is covered by the unit classification in TC-864 and by the store's own UT-162 for the open path; the write path shares its backoff schedule.
- `insert_row` with a value list that names a column that does not exist: the statement fails, the transaction rolls back, and the error is returned unchanged.

## Regression Scope

`doctask_service`, `doctask_flow` and `doctask_reconcile` (WP06 to WP08) call these methods and depend on the event hash tuple, the payload shapes, the legacy payload rule and the counter names; changing any of them changes persisted chains and must fail TC-862, TC-867 to TC-869 before any other module is changed. `Store` and `Engine` are used read-only by these tests: the tests in `tests/it_store.rs`, `tests/it_doctask_migration.rs` (IT-047, IT-073 and the probe tests) and `tests/it_engine.rs` must keep passing unchanged. The pure model tests (UT-141 to UT-146) must keep passing because the hashes come from `doctask_model`.
