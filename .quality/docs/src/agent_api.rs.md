# Technical Design: `src/agent_api.rs`

## Responsibility

`AgentApi` is the local-first, agent-facing read service over one `Engine`. It lists folders, reads files within a byte limit, answers whether remote transfer of a path is allowed, returns a file's version history with ledger-chain validity, and runs bounded regex search. It deliberately opens no network listener and trusts no caller-supplied tenant identity; authentication belongs to whatever adapter wraps it. `capabilities()` publishes the static capability table with the implementation status of each agent feature.

## Dependencies

- `engine::Engine` (workspace root, path resolution, file lookup, the transfer gate `remote_path_allowed` and `refresh_policy_if_stale`), `store::Store` (through the engine: `find_path`, `versions`, `verify_chain`), `search::grep` (regex search), `model::VersionRecord`.
- `serde::Serialize` for the response types `ResourceInfo`, `HistoryView`, `ApiCapability`; `anyhow` for errors; `std::fs`.
- Callers: the `agent-list` and `agent-capabilities` CLI commands in `src/entry.rs`, and the integration tests in `tests/it_agent_folder.rs`. The module comment names future MCP and IPC adapters; no MCP or IPC adapter calls `AgentApi` in the current source tree (`src/mcp.rs` and `src/doctask_mcp.rs` do not reference this module).

## Public Contract

- `capabilities() -> Vec<ApiCapability>` returns 21 entries: 6 with status `implemented`, 8 with `cli-implemented` and 7 with `design-only`. Each has a name, a status string and a `requires_approval` flag; 10 entries set the flag to true.
- `async list_folder(relative, limit) -> Result<Vec<ResourceInfo>>`: `limit` must be 1 to 1000 (error `limit must be 1..=1000`). The folder must exist, must not itself be a symbolic link (`symlink folder denied`), must resolve inside the workspace root (`folder escapes workspace`, which also applies to an absolute path outside the root) and must be a directory (`not a directory`). Entries that are symbolic links or junctions are skipped. Entries whose workspace-relative path starts with `.ladon` or `.git`, or equals `.LADONignore`, are hidden. These are string-prefix tests, so `.gitignore` and `.github` are hidden too; because the test uses the workspace-relative path, the rules match only entries directly in the workspace root. Each result carries the name, kind (`file` or `directory`), size in bytes, forward-slash relative path and the ledger file id when the path is tracked. Entries are kept in directory enumeration order until `limit` results are kept (hidden and link entries do not count), and the kept results are then sorted by name using bytewise string order (so `B.md` precedes `a.md`). Entry type and size come from `DirEntry::metadata`, which does not follow symbolic links. Each remaining entry is then passed to `Engine::remote_path_allowed`; an entry that the gate refuses is left out and does not count toward `limit`.
- `read_file_local(relative, max_bytes) -> Result<Vec<u8>>` (synchronous): `max_bytes` must be 1 to 8 MiB (`read limit must be 1..8MiB`). The path is resolved through `Engine::resolve`, which calls `archive::assert_under_workspace`: a path outside the workspace fails with `path escapes the workspace`, a symbolic link with `symlink capture forbidden`, and a directory or other non-regular file with `symlink/nonfile capture forbidden`. A regular file with a `.ladon` or `.git` component fails with `internal file cannot be tracked`. A file larger than `max_bytes` is rejected (`file exceeds caller limit`); otherwise the whole file is returned. The call is async: after the path resolves, `allow_remote_read` decides, and a refused path fails with `LADON policy denies external data transfer: <path>` before the size is read or any byte is returned.
- `async allow_remote_read(relative) -> Result<()>` refreshes the rules with `Engine::refresh_policy_if_stale` first, so a root or global rule file that cannot be loaded fails the call with its error, and then asks `Engine::remote_path_allowed(relative)`. When that returns `false` the call fails with `LADON policy denies external data transfer: <path>`; an `Err` from the engine is returned unchanged. The decision is the one the remote MCP path and the archive path use: the rule set in force (refreshed as described for `refresh_policy_if_stale`), the path rules of `LadonPolicy::allow_external`, the file's sensitive flag, and the content check of `content_is_excluded`. A path matched by the rules, any path under `.ladon` or `.git`, and any `.LADONignore` file itself are refused. A tracked copy of excluded content and a directory alias of it are refused, because the content check uses the file's current hash. A root rule file removed while the engine is open fails the call with the refresh error until the file is restored. Nested rule files take effect as the background traversal installs them (see `refresh_policy_if_stale`). Known limitation: a copy of excluded content that has not been captured is not refused, because the content check reads the ledger and not the bytes.
- `async history(relative) -> Result<HistoryView>` returns the file id, all versions newest first (by version number, descending) and whether the hash chain verifies (`Store::verify_chain`). Backslashes in `relative` are normalized to forward slashes before lookup, and an untracked path fails with `file not found in ledger`. No other normalisation is applied: a path with a `./` prefix, doubled separators, a `.` component, a different letter case or an absolute form fails with `file not found in ledger` even when the file is tracked (known limitation).
- `async grep_local(pattern, limit) -> Result<Vec<search::SearchHit>>` delegates to `search::grep` over the workspace root and keeps only the hits whose path `Engine::remote_path_allowed` allows. It asks `search::grep` for `limit` hits and asks again with twice as many, up to 100000, while refused hits leave fewer than `limit` and more hits may exist. A pattern longer than 512 bytes fails with `regex too long`, and the compiled expression is limited to 2 MiB. Hits are returned in directory walk order, each with the path relative to the workspace root (platform separators), the 1-based line number and up to 280 characters of the line. Files under `.git` or `.ladon`, files larger than 8 MiB, files whose metadata or content cannot be read (missing, locked or without permission) and files that are not valid UTF-8 are skipped; entries the directory walk cannot read are skipped as well. The search stops after the hit that makes the count reach `limit`, so a `limit` of 0 still returns one hit when the pattern matches; `limit` is not validated here. Known limitation: the `.git` and `.ladon` component check in `search::grep` tests the full entry path, so when an ancestor of the workspace root has either name, every file is skipped and the search returns no hits, without an error.

## Change Notes

- Folder entries are read with `DirEntry::metadata()`. The symlink check, the directory flag and the size come from one query that does not follow links.
