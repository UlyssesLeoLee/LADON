# Technical Design: `src/agent_api.rs`

Source: `src/agent_api.rs`

## Responsibility

`AgentApi` is the local-first, agent-facing read service over one `Engine`. It lists folders, reads files within a byte limit, answers whether remote transfer of a path is allowed, returns a file's version history with ledger-chain validity, and runs bounded regex search. It deliberately opens no network listener and trusts no caller-supplied tenant identity; authentication belongs to whatever adapter wraps it. `capabilities()` publishes the static capability table with the implementation status of each agent feature.

## Dependencies

- `engine::Engine` (workspace root, path resolution, file lookup, content exclusion check), `store::Store` (through the engine: `find_path`, `versions`, `verify_chain`), `policy::LadonPolicy` (external transfer rules), `search::grep` (regex search), `model::VersionRecord`.
- `serde::Serialize` for the response types `ResourceInfo`, `HistoryView`, `ApiCapability`; `anyhow` for errors; `std::fs`.
- Callers: the `agent-list` and `agent-capabilities` CLI commands in `src/main.rs`, and the integration tests in `tests/it_agent_folder.rs`. The module comment names future MCP and IPC adapters; no such adapter exists in the source tree.

## Public Contract

- `capabilities() -> Vec<ApiCapability>` returns 21 entries: 6 with status `implemented`, 8 with `cli-implemented` and 7 with `design-only`. Each has a name, a status string and a `requires_approval` flag; 10 entries set the flag to true.
- `async list_folder(relative, limit) -> Result<Vec<ResourceInfo>>`: `limit` must be 1 to 1000 (error `limit must be 1..=1000`). The folder must exist, must not itself be a symbolic link (`symlink folder denied`), must resolve inside the workspace root (`folder escapes workspace`, which also applies to an absolute path outside the root) and must be a directory (`not a directory`). Entries that are symbolic links or junctions are skipped. Entries whose workspace-relative path starts with `.ladon` or `.git`, or equals `.LADONignore`, are hidden. These are string-prefix tests, so `.gitignore` and `.github` are hidden too; because the test uses the workspace-relative path, the rules match only entries directly in the workspace root. Each result carries the name, kind (`file` or `directory`), size in bytes, forward-slash relative path and the ledger file id when the path is tracked. Entries are kept in directory enumeration order until `limit` results are kept (hidden and link entries do not count), and the kept results are then sorted by name using bytewise string order (so `B.md` precedes `a.md`). Entry type and size come from `DirEntry::metadata`, which does not follow symbolic links.
- `read_file_local(relative, max_bytes) -> Result<Vec<u8>>` (synchronous): `max_bytes` must be 1 to 8 MiB (`read limit must be 1..8MiB`). The path is resolved through `Engine::resolve`, which calls `archive::assert_under_workspace`: a path outside the workspace fails with `path escapes the workspace`, a symbolic link with `symlink capture forbidden`, and a directory or other non-regular file with `symlink/nonfile capture forbidden`. A regular file with a `.ladon` or `.git` component fails with `internal file cannot be tracked`. A file larger than `max_bytes` is rejected (`file exceeds caller limit`); otherwise the whole file is returned.
- `async allow_remote_read(relative) -> Result<()>` loads a `LadonPolicy` for the workspace root with `LadonPolicy::load` and checks the path with `allow_external`. The rule set is built from the file named by `LADON_GLOBAL_IGNORE` when that variable is set (a set variable whose file cannot be read makes the load fail), the root rule file (a file or link to a file directly under the root whose name is `.LADONignore` in any ASCII case), and every nested regular file named exactly `.LADONignore` at depth 2 or deeper, skipping `.ladon` and `.git` directories. A negated line in a nested file applies only below that file's directory, and pattern matching is ASCII case-insensitive on Windows. A rule file that does not parse, or a walk error such as an unreadable subdirectory, makes the call fail with that error. A path matched by the rules fails with `LADON policy denies external data transfer: <path>`; any path under `.ladon` or `.git`, and any `.LADONignore` file itself, is always excluded. An absolute path outside the workspace fails with `outside workspace`. `excluded` does not normalise `..` components: a relative path is joined onto the root, an absolute path is used as given, and the root-prefix check compares path components lexically, so a path that contains a `..` component is not rejected by the containment check (known limitation). After the path rules pass, the path is mapped to its ledger path with `Engine::relative_for_input`; a path that cannot be mapped is used as written, with backslashes replaced by `/`. When that ledger path is tracked and `Engine::content_is_excluded` returns true for the file's current hash, the call fails with the same `LADON policy denies external data transfer: <path>` message. A directory alias of excluded content is refused for this reason, because its path maps to the file's own ledger path. Known limitations: `LadonPolicy::load` does not check for the root rule file, so after that file is removed while the engine stays open, the remaining rules apply and an untracked path that the removed rules excluded passes; a copy of excluded content that has not been captured passes, because the content check reads the ledger and not the bytes.
- `async history(relative) -> Result<HistoryView>` returns the file id, all versions newest first (by version number, descending) and whether the hash chain verifies (`Store::verify_chain`). Backslashes in `relative` are normalized to forward slashes before lookup, and an untracked path fails with `file not found in ledger`. No other normalisation is applied: a path with a `./` prefix, doubled separators, a `.` component, a different letter case or an absolute form fails with `file not found in ledger` even when the file is tracked (known limitation).
- `grep_local(pattern, limit) -> Result<Vec<search::SearchHit>>` (synchronous) delegates to `search::grep` over the workspace root. A pattern longer than 512 bytes fails with `regex too long`, and the compiled expression is limited to 2 MiB. Hits are returned in directory walk order, each with the path relative to the workspace root (platform separators), the 1-based line number and up to 280 characters of the line. Files under `.git` or `.ladon`, files larger than 8 MiB, files whose metadata or content cannot be read (missing, locked or without permission) and files that are not valid UTF-8 are skipped; entries the directory walk cannot read are skipped as well. The search stops after the hit that makes the count reach `limit`, so a `limit` of 0 still returns one hit when the pattern matches; `limit` is not validated here. Known limitation: the `.git` and `.ladon` component check in `search::grep` tests the full entry path, so when an ancestor of the workspace root has either name, every file is skipped and the search returns no hits, without an error.

## Change Notes

- Folder entries are read with `DirEntry::metadata()`. The symlink check, the directory flag and the size come from one query that does not follow links.
