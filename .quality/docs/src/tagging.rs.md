# Technical Design: `src/tagging.rs`

Source: `src/tagging.rs`

Source-SHA256: `ae4d8561bcfe1e5c68928c33914df0138edacdc21308b422fa0e73ab2d8a3560`

## Responsibility

Produces classification tags for tracked documents in two ways: a deterministic keyword rule table (`heuristic_tags`) that works offline, and an optional call to an OpenAI-compatible chat endpoint (`ai_tags`) that returns a short JSON array of tags. It also decides whether an endpoint is local (`local_endpoint`). It never contacts a remote service unless the caller passes an endpoint, and it refuses remote plain-HTTP endpoints.

## Dependencies

- `anyhow` for errors, `serde_json` for request and response bodies, `url` for endpoint parsing, `reqwest` (default features off; `json` and `rustls-tls-native-roots`) for the chat request, so HTTPS certificates are checked against the system certificate store, `std::env` for the optional `LADON_AI_API_KEY` bearer token, `std::time::Duration` for the request time budget. The HTTP client honours the standard proxy environment variables for remote endpoints; loopback endpoints ignore them.
- Callers: the `tag-folder` CLI command in `src/entry.rs` (`tag_folder`). For each tracked file it reads at most the first 16384 bytes and calls `heuristic_tags` on that text. It calls `ai_tags` only when an endpoint and a model are given; for a file excluded by `.LADONignore`, or whose content `Engine::content_is_excluded` reports as excluded, it calls `ai_tags` only when `local_endpoint` accepts the endpoint, and otherwise skips the AI call with a message. The stored source is `ai+rules` whenever an endpoint and a model are given, including for a file whose AI call was skipped (known limitation). Untracked files and walker errors are skipped without a message (known limitation). A tracked file overwritten with excluded bytes but not yet captured is judged by its old ledger hash (known limitation). `LadonPolicy::excluded` fails a path that contains a `..` component with `outside workspace`. The returned tags are persisted through `store::Store::set_tags`.

## Public Contract

`heuristic_tags(path, text) -> Vec<String>`: lowercases `"{path} {text}"` and walks the rule table in order. A label is emitted once when any of its keywords is a substring of that string. The table is `[(&str, &[&str]); 8]` with these labels in this order: `requirements`, `basic-design`, `detailed-design`, `unit-test`, `integration-test`, `system-test`, `rust`, `nema`. Each row stores its keywords as a slice; the keyword counts are 4, 4, 4, 4, 3, 3, 3 and 4 in the label order above. Keywords are compared as written against the lowercased string, so every keyword in the table is lowercase, and Chinese, Japanese and English keywords are matched alike. Matching is a plain substring test, so the short keywords `ut-`, `it-` and `st-` also match inside longer words: the path `input-a.md` yields `unit-test`. The result is empty when nothing matches.

`local_endpoint(endpoint) -> Result<bool>`: parses the URL, accepts only `http` and `https` schemes (error `http(s) endpoint only`), and returns true for the hosts `localhost`, `127.0.0.1`, `::1` and `[::1]`.

`ai_tags(endpoint, model, description, filename, preview) -> Result<Vec<String>>` runs `ai_tags_with_timeout` with `AI_REQUEST_TIMEOUT` (60 seconds). That budget covers the whole request, including reading the response body. `ai_tags_with_timeout` is `#[doc(hidden)]`: it takes the same arguments and an explicit `Duration`, and exists so that tests can use a shorter budget. The function first calls `local_endpoint`, so a non-http(s) scheme (`http(s) endpoint only`) or an unparsable URL fails before any request. It rejects a non-local endpoint that does not start with `https://` (error `remote AI requires https`). A remote endpoint's certificate is checked against the system certificate store, through the reqwest feature `rustls-tls-native-roots` with default features off. For a loopback endpoint the client is built with `no_proxy()`, so the standard proxy environment variables do not apply to it; a remote endpoint uses them as the default client does. It posts a chat completion request (temperature 0, a system prompt requiring a JSON array of 1 to 8 short lowercase tags, the preview limited to its first 6000 characters); it adds a bearer header when `LADON_AI_API_KEY` is set. Redirects are not followed: a 3xx status fails with `AI endpoint answered with HTTP <status>; redirects are not followed`, and any other non-success status fails through `error_for_status`. The response body is read in chunks and rejected with `AI response exceeds 8388608 bytes` as soon as it would pass 8 MiB; a body of exactly 8 MiB is accepted. A body that is not JSON fails while it is parsed. It reads `choices[0].message.content`, which is the error `missing chat content` when absent, strips optional Markdown code fences (with or without the `json` marker) and parses a JSON array of strings (error `AI response was not a JSON tag array`). It drops blank or whitespace-only tags and tags longer than 80 bytes (the length is counted in bytes, not characters), leaves the remaining tags unchanged, and returns at most the first 8 of them. The cap applies after filtering.

## Change Notes

The rule table has type `[(&str, &[&str]); 8]`: it holds eight labels, each with a slice of keywords. Matching is a case-insensitive substring test over the path and the text, label order is the table order, endpoint validation is as specified above, and the chat protocol is the OpenAI-compatible request and response shape described under Public Contract.
