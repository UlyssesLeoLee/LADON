# 25. セキュリティ・運用基本設計書

## 1. 权限边界
普通用户/管理员/Agent/外部插件的访问最小化。所有向 Google Drive、NAS、网络模型、外部插件、MCP 的用户数据出站前必须执行敏感规则及用户授权，未加载规则或规则解析错误必须 Fail-closed。当前实现：根规则（全局规则文件与根目录 `.LADONignore`，根目录文件名按 ASCII 大小写不敏感匹配）解析错误时 `Engine::init` 与 `Engine::open` 返回错误；嵌套规则文件的解析错误与工作区内无法遍历的目录（遍历错误）在后台全量扫描中发现，此后记录（`Engine::capture`）与外部归档（`Engine::archive_version`）等待扫描结束并返回该错误，不执行操作；根规则（全局规则文件与根目录 `.LADONignore`）热加载校验失败时 `Engine::reload_policy` 将 `policy_valid` 置为假，`Engine::archive_version` 随之拒绝全部外部归档；嵌套规则文件的错误不影响 `policy_valid`。嵌套 `.LADONignore` 中的排除模式以工作区根为基准解释，对整个工作区生效，不限于其所在目录；其中的 `!` 例外规则只作用于该文件所在目录及其子目录（不带斜杠的模式匹配该目录下任意层级，带斜杠或以斜杠开头的模式以该目录为锚点）。全局文件与根 `.LADONignore` 中的 `!` 例外不受此限制，对整个工作区生效。嵌套规则文件仅识别名称精确为 `.LADONignore` 的文件，`watch` 对根目录规则文件按任意 ASCII 大小写名称重新加载，对嵌套规则文件仅对精确名称的变更重新加载；`watch` 对每个事件批次中的路径逐一处理：根规则文件与名称精确为 `.LADONignore` 的文件重新加载规则（不捕获）；普通文件执行捕获；其他路径（已删除或为目录）把台账中同一相对路径的文件标记为已删除。批次中有路径不是普通文件、且不是根规则文件时（`policy::needs_full_scan`），该批次处理后执行一次完整工作区扫描，代价为完整遍历；该判定由 `ut_needs_full_scan_for_directory_events` 覆盖，`watch` 循环本身无自动化测试；Windows 监听缓冲区溢出时的变更不补偿（已知限制）；Windows 上规则模式按 ASCII 大小写不敏感匹配。规则文件自身的固定排除同样仅对该精确名称生效，名称大小写不同的根规则文件当前未被固定排除，可被纳入历史并外传，该保护未实现。根目录 `.LADONignore` 缺失时，`Engine::open` 与 `LadonPolicy::check_root` 返回错误（`root rule file .LADONignore is missing`），`Engine::reload_policy` 将规则集标记为失败，内核与图形界面的记录和外部归档均拒绝；`LADON_GLOBAL_IGNORE` 未设置时不加入全局规则，设置为空字符串或指向不存在、不可读的文件时，`LadonPolicy::load` 与 `check_root` 失败（fail-closed）；指向存在的空文件时不增加规则。运行路径中已接入的出站检查为 `Engine::archive_version`（由 CLI 的 `src/main.rs` 与 ui-prototype 的归档命令调用，经 `LadonPolicy::allow_external`，对传入的任意 `StorageProvider` 生效；版本或同一内容哈希的任一版本被标记为敏感、当前路径被排除，或账本中曾持有同一内容哈希（含历史版本）的任一路径被排除时拒绝）与 `tag-folder` 命令的远端 AI 请求（文件被排除，或其台账中的内容哈希被排除（`Engine::content_is_excluded`）时，仅允许 `localhost`、`127.0.0.1`、`[::1]` 的本地模型，远端请求被跳过；回环端点的请求忽略代理环境变量，远端端点保持默认代理设置；已知限制：文件被覆写为排除内容但尚未捕获时，仍按台账中的旧哈希判定；该跳过分支无自动化测试）；`AgentApi::allow_remote_read` 与 `cloud_journal::publish_segment` 中的敏感检查目前仅由测试调用，未接入运行路径。`allow_remote_read` 为异步判定，拒绝规则排除的路径，以及内容被排除的已跟踪文件的副本与目录别名（`tc410_allow_remote_read_refuses_copy_of_excluded_content` 通过）；该判定以账本中的内容哈希为准，未记录路径的副本与磁盘上已改动但未捕获的文件不被检测（已知限制）；它以 `LadonPolicy::load` 加载规则，该加载不检查根规则文件，根规则文件缺失时不拒绝（已知限制，RSK-19）。`LadonPolicy::excluded` 不规范化 `..` 分量，含 `..` 的路径（相对路径，或规范化根之下的绝对路径）不被工作区外检查拒绝（已知限制，当前实现未处理）。CLI 的 history、verify、tags、annotate、task 接受普通 Windows 绝对路径：以工作区根为前缀的路径直接取相对部分；其他绝对路径以其父目录规范化并拼接文件名后检查位于工作区内（`Engine::relative_for_input`），文件本身可以不存在，父目录不存在时失败（已知限制）。相对路径输入经 `engine::normalise_relative` 处理（反斜杠换为 `/`，去除空组件与 `.` 组件，由 `resolve_record` 使用；测试 `normalise_relative_drops_dot_components` 通过）；`..` 组件与大小写差异不做规范化，台账精确查找失败（已知限制）。源码中尚无外部插件与 MCP 的出站路径。

## 2. 凭据
私钥/Google OAuth Refresh Token/AI Key 不写入 Turso 一般表、源代码、CLI 参数或 `.NEMA` 文档。访问令牌、客户端密钥、归档密钥与 AI 密钥的生产计划采用 Windows Credential Manager / DPAPI 或受支持系统密钥链。本期访问令牌（`LADON_GOOGLE_ACCESS_TOKEN`）、客户端密钥（`LADON_GOOGLE_CLIENT_SECRET`）、归档密钥（`LADON_ARCHIVE_KEY_HEX`，64 位十六进制）与 AI 密钥（`LADON_AI_API_KEY`）仍从环境变量读取，应避免终端回显与系统共享环境泄露。

Google Drive 登录（`ladon google-login`）采用 OAuth 2.0 授权码流程与 PKCE（S256），回环重定向为 `http://127.0.0.1:<临时端口>/`，申请范围仅为 `drive.file`，并请求离线访问（`access_type=offline`、`prompt=consent`）。`state` 为随机值，回调中的 `state` 不一致即登录失败；本地监听只处理第一次到达的连接。客户端 ID 读取 `LADON_GOOGLE_CLIENT_ID`（必需），客户端密钥读取 `LADON_GOOGLE_CLIENT_SECRET`（可选，仅来自环境变量）；Google 可能要求桌面类客户端提供客户端密钥，此时需设置该变量。

在 Windows 上，授权地址由默认浏览器打开，经 `rundll32 url.dll,FileProtocolHandler` 的命令行参数传入，不在标准输出中显示。授权地址包含 `state` 与 `code_challenge`，会出现在命令行参数与浏览器历史中；不包含 PKCE 验证器与令牌。非 Windows 环境下不会打开也不会显示授权地址；在设置目录可解析且已设置 `LADON_GOOGLE_CLIENT_ID` 的前提下，非 Windows 环境的登录等待 5 分钟后报告「sign-in timed out」，不进入保存步骤。设置目录不可解析（`LADON_SETTINGS_DIR` 与 `LOCALAPPDATA` 均未设置或为空）时，`ladon google-login` 与 `ladon google-logout` 立即报告「no settings folder: set LOCALAPPDATA or LADON_SETTINGS_DIR」。

刷新令牌只以 DPAPI 加密后的形式保存（`CryptProtectData`，不使用附加熵，当前用户范围，不弹出界面），保存位置为设置文件夹（`LADON_SETTINGS_DIR`，未设置时为 `%LOCALAPPDATA%\LADON`）中的 `google-token.bin`，经临时文件改名写入。刷新令牌不写入 Turso 数据库，默认保存位置在工作区之外。DPAPI 使其他 Windows 用户无法解密该文件，文件被复制到其他机器后也无法解密；同一用户下运行的其他进程仍可解密，因此不防御同一用户的恶意程序。访问令牌不落盘：使用已保存的登录时，每次上传或读取前以刷新令牌换取访问令牌，上传会话与内容请求共用同一令牌。令牌端点只接收 OAuth 参数（授权码、验证器、客户端 ID 与密钥，或刷新令牌），不含文件内容或路径。

令牌交换失败时报告 HTTP 状态码或网络、应答格式的固定分类；刷新失败时只报告固定文言「access token refresh failed」，不含状态码。两者均不含响应正文、令牌、授权码或客户端密钥，令牌与客户端密钥的调试输出均被遮蔽。Google 未返回刷新令牌时，报告要求在 Google 账号中撤销 LADON 的访问权限后重新登录。`ladon google-login` 与 `ladon google-logout` 的标准输出只有固定文言。`ladon google-logout` 只删除本地的 `google-token.bin`，不撤销 Google 侧的授权。非 Windows 环境下保存函数报告「protected storage is available on Windows only」。

Google Drive 的凭据选择：去除首尾空白后非空的 `LADON_GOOGLE_ACCESS_TOKEN` 优先；未设置、为空或仅含空白时读取已保存的登录。设置目录不可用、令牌文件不存在，或未设置 `LADON_GOOGLE_CLIENT_ID` 时，报告「Google Drive is not connected」（令牌文件存在且可读但未设置 `LADON_GOOGLE_CLIENT_ID` 时，同样报告该文言，不给出缺少客户端 ID 的原因，已知缺陷，见 00 号文档第 1.5 节）；令牌文件存在但无法读取（读取失败、DPAPI 解密失败或内容为空）时，报告「stored sign-in is unreadable」。ui-prototype 的设置页与 Google Drive 归档只检查 `LADON_GOOGLE_ACCESS_TOKEN` 是否非空（不做去除空白处理），检查本身不读取已保存的登录，也不把令牌值传给界面。若该变量仅含空白字符，界面检查通过，归档时内核将其视为未设置，改读已保存的登录。

验证状态：2026-11-24 的根 crate debug `cargo test` 全量运行结果为 167 项通过（库单元测试 80 项与集成测试 87 项）、0 失败，覆盖该运行时 Windows 下编译的全部测试函数（仅 unix 编译的 ut_policy_symlinked_root_rule_file_is_applied 与非 Windows 编译的 tc805_protected_storage_is_windows_only 不在 Windows 上编译）。`tests/it_google_oauth.rs` 中 Windows 下编译的 10 个测试函数为 tc801 至 tc809 系列；其中 tc808 向令牌端点 `https://oauth2.googleapis.com/token` 发送一次使用假授权码的真实 HTTPS 请求，未以真实账户完成，测试断言回调应答为 `HTTP/1.1 200 OK` 且包含固定 HTML 页面、错误信息以「token exchange failed」开头，且错误信息中既不含授权码也不含 state，不调用 Drive。手工检查 TC-813（`ladon google-logout`，无已保存的登录）、TC-814（`ladon google-login`，未设置 `LADON_GOOGLE_CLIENT_ID`）与 TC-815（`ladon google-login`，使用客户端 ID 并完成浏览器授权）均未执行；使用真实 Google 账户的登录与令牌交换未执行（TC-815）。HTTPS 客户端（Google 令牌端点、Drive 与远端 AI 端点）使用 reqwest 的 rustls-tls-native-roots 特性，证书链验证以 Windows 系统证书存储为根，企业 TLS 检查所用的根证书可被信任；在经 TLS 检查的网络上的验证未执行。

## 3. 备份与恢复
历史内容自管理不可变对象；Provider 写完不代表备份可恢复，必须读回校验。DB 是索引与事件热点状态，未来需一致性快照/定期 checkpoint 上传受审计的非敏感部分。敏感数据与对应元数据专用本地备份（或用户明确授权的私有介质）。

恢复（`Engine::restore`，CLI 的 `restore` 与图形界面的版本恢复共用）：未经批准的恢复被拒绝。恢复前，现有文件无法读取时返回读取错误；其摘要与台账记录的当前摘要不一致时，拒绝并报告「live file changed outside ledger; scan before restore」。历史字节取自本地 CAS；本地没有该内容时，由归档 Provider 读回，经归档密钥解密并按版本摘要校验后使用。随后依次执行：将恢复字节写入临时文件；将现有文件改名为备份文件；重新计算备份文件的摘要（64 KiB 分块），与台账摘要不一致时将备份放回原位并报告相同错误；将临时文件以不替换已有文件的方式放置到目标（硬链接；卷不支持硬链接时以 `create_new` 复制，目标已存在则失败）；以操作者 `restore` 记录新版本，记录成功后删除备份文件，删除失败时恢复仍报告成功并保留备份（已知行为）。临时文件、备份文件与移开的文件位于工作区的 `.ladon/restore` 目录（与目标在同一卷，改名保持原子性），扫描、监听与 tag-folder 跳过 `.ladon` 目录。放置时目标已出现文件（恢复期间出现的文件）的，该文件保持不变，恢复报错并给出目标路径；有现有文件时同时给出备份路径，并保留备份。记录失败时，目标文件仍为恢复字节则移除目标并还原备份（无现有文件时仅移除目标）；目标文件已被改动或无法读取则保留目标与备份，报错信息给出目标与备份路径（无现有文件时仅保留目标）。移开目标失败（例如目标被占用）时，报错文本称目标已不再为恢复字节，该说法仅在已完成摘要复核时成立，未复核时目标仍可能为恢复字节（已知限制，见 00 号文档第 1.5 节）。还原备份与放回移开文件使用的改名为 `fs::rename`，会替换回滚期间出现在目标路径的文件（已知限制，未修复，见 00 号文档 RSK-18）；还原备份的改名失败时其错误被忽略，报错不给出备份路径（同一已知限制）。摘要以 64 KiB 分块计算，结果与整文件摘要一致。

删除（ui-prototype 的 `delete_path`）：路径先经相对路径与存在性检查，内部目录与规则文件被拒绝；随后经系统回收站移动该文件或文件夹（`SHFileOperationW`，标志组合为允许撤销、不再次确认、静默、回收站无法接收时询问是否永久删除）。外壳未完成移动（含用户取消永久删除的询问）时返回删除失败，台账不变。移动完成后，台账中该路径及其下未删除的记录标记为已删除，操作者为 `human`；标记失败时返回删除失败（已知缺陷，见 00 号文档第 1.5 节）。完整路径超过 MAX_PATH 的项目无法移动（已知缺陷）。非 Windows 构建中该操作始终返回删除失败。

## 4. 运行与监控
事件队列长度、待备份对象、历史错误数、最后校验时间、CAS 占比、Agent 并发、UI 延迟应可观测。对云端配额不足、令牌失效、磁盘剩余低、历史对象失联弹出清晰报警。允许手工触发校验和修复，不做偷偷的删除。

## 5. 启动模式
Cold：原生 GUI→文件浏览→后台 Worker 可启动；Warm：常驻进程时重新打开窗口；两种模式分别测量。无后台常驻也必须正确运行。对资源繁忙系统优先保证交互。

## 6. 灾备 RPO/RTO
设计目标：本地未上传日志 RPO=0（本地磁盘仍存活且捕获完成时）；远端 RPO 由同步延迟界定；历史恢复 RTO 由对象大小和网络性能决定，需 ST 实测后定 SLA。不能将断网时尚未捕获的文件事件错误标记为云端已保护。

## 7. 安装与卸载
Windows 安装向导由 `Setup.cmd` 启动（以 `-ExecutionPolicy Bypass` 调用 `Install-LADON.ps1`），按当前用户安装，不需要管理员权限，写入范围限于当前用户（安装目录可在向导中改选，但不请求管理员权限）：安装目录（默认 `%LOCALAPPDATA%\Programs\LADON`；目录非空且不存在 `install-manifest.json` 时拒绝）、用户 PATH（可选，把安装目录按完整路径精确匹配（忽略大小写与末尾反斜杠）追加到 `HKCU\Environment` 的 `Path`，保持原有 `%变量%` 展开形式，写入后广播环境变更通知）、开始菜单项（可选，位于 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\LADON`，内含「LADON 命令行」与「卸载 LADON」两个快捷方式）、「已安装的应用」登记（可选，写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\LADON`，显示名称为「LADON（试用构建）」）和示例工作区（可选，默认 `%USERPROFILE%\LADON-Sandbox`，仅在目录不存在时创建，写入 `requirements.md`、测试用 `secret.pem` 并复制 `QUICKSTART.txt`，自检通过后对其执行 `init`，成功时再执行 `scan`）。安装目录内复制程序（`ladon.exe`）、图标、许可证、默认配置、示例规则、说明文件与三个 PowerShell 脚本（`LADON-Shell.ps1`、`LADON-Common.ps1`、`Uninstall-LADON.ps1`），图形程序 `ladon-gui.exe` 不由向导复制，向导也不创建其开始菜单项；安装包缺少 `ladon.exe`、`Uninstall-LADON.ps1`、`LADON-Shell.ps1` 或 `LADON-Common.ps1` 时拒绝安装。每次安装写入 `install-manifest.json`，记录实际创建的内容（安装中途失败时也写入已完成的部分；重复安装时沿用清单中已有的 PATH、示例工作区、快捷方式和登记记录，文件列表记录复制结果）。卸载程序 `Uninstall-LADON.ps1` 只按清单还原：移除「已安装的应用」登记；仅当清单记录由安装程序加入 PATH 时移除该条目；删除清单中的快捷方式，开始菜单文件夹为空时一并删除；删除清单中的文件（含清单本身），清理后变为空的 `config\examples` 与 `config` 目录一并删除；示例工作区仅当清单记录为安装时新建，且用户在对话框中选择「是」或传入 `-RemoveSample` 时才整体删除（含其中的 `.ladon` 历史）。随后卸载程序退出，由延迟执行的隐藏 cmd 删除自身两个脚本，再以不带 `/s` 的 `rmdir` 删除安装目录（仅在目录已空时成功，否则保留）；清单缺失时卸载程序直接退出。卸载程序不删除其他工作区的 `.ladon` 历史，也不删除设置文件夹（`LADON_SETTINGS_DIR` 或 `%LOCALAPPDATA%\LADON`，其中可能有 `google-token.bin` 与 `nas-folder.txt`）；`ladon google-logout` 只删除本地保存的登录，不撤销 Google 侧授权。安装开关为 `-Silent`（无界面）、`-NoPath`、`-NoShortcuts`、`-NoSample`、`-NoRegister`，以及 `-InstallDir`、`-SampleDir`、`-StartMenuRoot`、`-RegistryName`、`-PayloadDir`、`-ScreenshotDir`（仅渲染向导页面截图，不安装）；卸载开关为 `-Silent`（无界面，示例工作区默认保留）、`-RemoveSample`、`-InstallDir`。安装包由 `Build-Package.ps1` 生成，随附 `SHA256SUMS.txt`（脚本不校验该文件），zip 需完整解压后运行 `Setup.cmd`；安装与卸载不访问网络；安装后运行 `ladon --version` 自检，失败即报告安装失败，示例工作区初始化失败只给出提示。

按用户安装的 MSI（`packaging/windows/msi/LADON.wxs`，由 `build-msi.ps1` 以 WiX 5 生成，未安装验证）安装到同一默认目录，安装 `ladon.exe` 与 `ladon-gui.exe` 及说明文件，把安装目录加入用户 PATH（Environment 元素），创建开始菜单「LADON」文件夹下的「LADON」快捷方式（指向 `ladon-gui.exe`），并写入 `HKCU\Software\LADON\Explorer` 的 `Installed`（值为 1）。MSI 不写入 `install-manifest.json`，不创建示例工作区。向导拒绝非空且无清单的目录，因此 MSI 装入的默认目录不被向导识别为其安装目录；MSI 不检查安装清单，可覆盖该目录中的同名文件；两者不共享安装记录，同名文件（如 `ladon.exe`）可被任一方的卸载删除。

已知限制（未修复，见 00 号文档第 1.5 节）：安装程序的卸载顺序、MSI 与 zip 安装包之间的冲突检测、相对安装路径；PATH 中已存在末尾带分号的同一目录时仍记为新增。
