## 2. 依赖方向
UI→Application→Core Model/Governance→Repository/Storage。禁止 UI 直接运行 Google Drive API；禁止插件绕过 `PolicyGate`；禁止业务层直接通过数据库路径构造 SQL；将 API/Provider 错误映射成统一 Error 类型。

## 3. 服务时序
`watcher()` 接收 OS 文件事件→去重队列→`Engine.capture`→`CasStore.put_file`→`Store.append_version`；业务触发 `ArchiveService.archive`→`LadonPolicy.allow_external`→`Crypto.seal`→`Provider.put`→`Provider.get`→`Crypto.open+SHA verify`→`Store.archive_record`→按策略 `CasStore.evict`。

## 4. 接口分离
文件读取（File Reader）、增量 Diff（Document Parser）、文件内容归档（Version Object Store）、事件账本（Event Store）、远端存储（Provider）、Agent 执行（Command Bus）、模型（AI Provider）是不同的接口契约，避免把“文件身份”“云盘文件 ID”“向量 ID”混为一个概念。

## 5. 拓展规则
所有 Provider 声明 `supports_range_read`, `supports_native_resume`, `atomic_put`, `storage_quota` 能力，调用端按能力分支；不支持远程续传不自动降级为不安全静默传输。
