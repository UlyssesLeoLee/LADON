# 23. データ・ストレージ基本設計書

## 1. 数据对象分类
| 类型 | 热存储 | 冷存储 | 是否包含用户原件 | 敏感规则 |
|---|---|---|---|---|
| file metadata | Turso | 事件索引可选备份 | 否 | 同步时脱敏或禁止 |
| versions/events | Turso | 分段归档 | 事件详情可能敏感 | 外传策略检查 |
| content CAS | Zstd 本地 | Google Drive/NAS 等 | 历史快照（非原件） | 敏感内容本地保留 |
| annotations/tasks | Turso | 受控备份 | 可能包含敏感原因 | 字段级分类 |
| tags/vectors | Turso 热标签 | 冷索引可重建 | 内容派生可能敏感 | 按内容同等级别 |
| Git Worktrees | 用户磁盘 | 完整恢复 Manifest | 是 | 未验证前禁止清理 |

## 2. Turso 表清单
`resources`, `versions`, `events`, `archive_objects`, `file_tags`, `annotations`, `doc_tasks`, `graph_edges`, `embeddings`, `backup_jobs`, `governance_events`。详细 DDL 位于 `sql/001_initial.sql`，参见详细设计 30/32。

## 3. 内容寻址与引用
CAS Key 为历史**明文** SHA-256（64 Hex）；本地对象压缩，云对象为压缩+随机 Nonce AES-256-GCM。相同 Hash 在本地唯一；远端每 `(hash,provider)` 只有一条通过验证的定位引用；对象的完整可读性在恢复时再次验证。不要用 Google Drive 文件 ID 作为逻辑版本 ID。

## 4. Cloud Storage 策略
Google Drive 优先使用用户指定单独备份目录，上传使用 resumable API，远端为不可变自管理对象。每个对象需具 `hash`, `provider`, `locator`, `encryption`, `verified_at`。异步队列是最终目标；当前 CLI 归档同步等待结果且密钥必须通过环境变量提供。

## 5. 向量存储策略
P1 采用 Turso 单库优先评估向量检索：按 `(content_hash, model_id, chunk_id)` 去重，模型和向量维度必须绑定，内容变更仅重算变化块；量化以实际 Recall/Latency 为准。当前 `embeddings` 表仅结构预留，不表示已有生成或 ANN 搜索能力。

## 6. Worktree 减容策略
先计算工作区磁盘体积与 Git 共享对象；优先释放 `target`, `node_modules` 等可再生缓存。冻住工作区时保存 HEAD、index、stash/uncommitted patch、未跟踪文件、权限和 LFS/子模块引用等，完成恢复演练才可建议回收。仅 Git Bundle 不足以备份未提交更改。

## 7. 数据库同步安全
默认 Turso Local-only。今后 Turso Cloud 同步必须额外设计敏感字段隔离或独立 DB/加密 envelope，不能因为数据表本身很小就自动云同步。
