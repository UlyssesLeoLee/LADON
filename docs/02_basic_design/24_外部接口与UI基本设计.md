# 24. 外部・内部インタフェース基本設計書

## 1. 逻辑业务 API
| 方法 | 输入 | 输出 | 权限 | 状态 |
|---|---|---|---|---|
| `POST /v1/workspaces` | root, policy | workspace_id | 管理员 | CLI init 已覆盖 |
| `POST /v1/files/capture` | path, actor, reason | FileRef, Version, Event | 用户/Agent | Rust 实现 |
| `GET /v1/files/{ref}/history` | file_ref, cursor | 事件/版本分页 | 授权读 | CLI history（未分页） |

| `POST /v1/folders/{ref}/tag-plan` | preset, prompt | plan | AI 权限 | CLI tag-folder 局部 |

**协议说明：** 表中 `/v1` 是统一逻辑资源 API，计划由 Rust IPC、CLI、MCP 或未来 HTTP 服务暴露；**不表示当前已经启动 REST 服务器**。

## 2. 认证和访问
- 本地：OS ACL + 用户确认，独立 Agent 进程不得越过其 FileSpace 范围。
- Google Drive：OAuth 2.0 `drive.file` 等最小权限，经用户交互授权，Token 存 Windows 凭据存储；当前原型通过 env token 单次调用。
- NAS：挂载目录由 OS 身份负责；后续 SMB/WebDAV Provider 单独封装凭据。
- AI：本地 Ollama 可以用 loopback HTTP，远端需要 TLS 与敏感排除判定，不能在历史事件中写入 API key。

## 3. API 错误码设计
`LADON-POLICY-403` 外传禁止；`LADON-VERSION-409` 版本已变；`LADON-CAS-422` 哈希不符；`LADON-CLOUD-503` 提供商不可用；`LADON-AUDIT-500` 事件链受损；`LADON-SPACE-429` 资源限流。错误返回包含 `code`, `message_key`, `correlation_id`, `retryable`。

## 4. 迁移路径
Provider API 接口优先固定 `put_immutable_object`, `get_object`, `delete_object`, `head`, `get_capabilities`, `resume_upload`, `quota`, `health_check`。可组合实现不能用所有 Provider 原生能力的操作；Provider 支持程度以 Capability Manifest 显示。
