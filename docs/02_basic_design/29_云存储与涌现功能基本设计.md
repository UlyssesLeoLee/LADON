# 29. 基本設計 — 分层同步与涌现式治理

## 1. 最小外部调用

个人本地浏览、索引、Diff、任务提示原则上不经 Vercel；只有确实需要身份协作的共享工作空间访问才依赖控制面。Drive API 调用仅由后台执行，且尊重配额和限流。

## 2. 设计涌现

用户动作 + 文件事件 + 要件指纹 + 任务状态 + 测试结果 → 事件融合 → 证据评分 → **建议** → 人工审批 → Agent 在 FileSpace 中执行 → CommitCoordinator 校验 → HistoryLedger 归档 → 下一轮增量反馈。

规则先行，不能把同一个文件事件的多个复制信号算作独立证据；没有两类证据和可信条款锚点不激活模型。定期评估误报/漏报、token 预算与性能成本。
