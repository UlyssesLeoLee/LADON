# 15. 要件定義書 — LADON V1.3 增量要件

- 基线：V1.2 REQ-001～072 不删除；V1.3 新增 REQ-073～100。
- 分类：**P0 强制**优先确保本地历史、远端可靠性、敏感数据保护与 UI 原生速度；其余 P1 分阶段。
- 业务目的：个人文档历史不依赖常驻服务器；组织多租户必须经可信身份/权限控制服务；文件和聊天尽量在用户自主选择的云存储归档。
- 标准映射：IPA 共通フレーム中的要求定义→架构/详细设计→实现→単体/結合/総合/受入测试，属于自定义工程交付件，不是 IPA 官方认证模板。

## 1. 业务参与者与责任边界

| 主体 | 权限 | 禁止事项 |
|---|---|---|
| 个人用户 | 本机管理、云盘 OAuth 授权、自行存储 | 默认将 `.LADONignore` 文件或隐私元数据传输远端 |
| 企业管理员 | 租户成员/密钥策略/工作空间配置 | 直接窃取成员本机 OAuth refresh token |
| 项目编辑成员 | 授权的文件变更、文档任务、聊天 | 访问其他租户文件和历史 |
| Agent | 根据授予权限使用 FileRef/Folder API 并提出变更 | 绕过提交审批/敏感策略/租户服务端授权 |
| 云存储供应商 | 保存加密后的历史对象 | 作为 LADON 成员/权限判定权威 |
| Vercel 控制面 | 身份验证、成员关系、设备、密文消息协调 | 承载完整文件原件与历史内容 |

## 2. 完整要件与验收

单一事实源：`design/requirements.json` 的 REQ-073～100（含优先级、实现路径、验收条件）；追踪到 `docs/04_tests/要求追踪_测试管理.xlsx`。原 REQ-001～072 保留不变。

## 3. 核心接受条件（阻断项）

1. 个人本机模式：零登录、零网络仍可浏览和产生本地文件历史。云盘连通后，完整被捕获历史可经加密不可变对象恢复。
2. `appDataFolder` 仅限个人应用数据，无法用作成员共享后端；团队通过共享普通目录/Shared Drive 保存密文对象。
3. 团队工作区必须双重授权：Vercel 服务端成员验证 + Google Drive/NAS 实际存储访问权；不得只靠浏览器/客户端隐藏。
4. `.LADONignore` 作用于原件、文件名、路径、事件正文、索引、聊天附件及 AI 外传。规则错误时拒绝向外传输。
5. UI 主栏随侧栏宽度变化自适应填满；Hover 只覆盖不触发布局跳变。底部聊天固定最下沿，展开向上延展。
6. 非危险通知动态淡出；备份失败、敏感拦截、历史缓冲耗尽及冲突等安全类通知不淡出。
7. 按设备追加事件段、完整性证明、跨设备冲突必须可核查。缺口可报告，不得伪造“历史完整”。
8. 双信号产生基于证据的推荐，但不产生未经批准的文档/测试写入。

## 4. 验收前提

工作区已经存在批准过的要件定义文件；V1.3 不自动重建原始要件。用户审批后才能改变基线。未安装 Windows 11/Google OAuth 的构建环境只能证明静态规范，不能写作已验收。
