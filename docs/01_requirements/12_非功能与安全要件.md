## 2. 威胁模型（STRIDE 归纳）
- Spoofing：Agent 身份/Token 仿冒→会话隔离、来源审计、OAuth 最小权限（`drive.file`）、PKCE 与 state 校验。
- Tampering：事件日志篡改→每文件事件哈希链、备份签名/校验点计划。
- Repudiation：无法证明人/Agent 操作→操作者 ID、任务 ID、受控命令总线。
- Information Disclosure：远端 AI、云盘、向量/插件泄密→`.LADONignore` Fail-closed、元数据脱敏、外传拦截、Google 刷新令牌的当前用户范围 DPAPI 保护、令牌与密钥不进入提示或日志。
- Denial：大量目录/巨型文件/模型任务阻塞 GUI→IO 池、限流、逐块处理、独立 Worker；外部请求的时限与应答上限（NFR-030）。
- Elevation：插件越权操作系统目录→路径正规化、原生 ACL 校验、沙箱、审批。

## 3. 敏感策略细分
拒绝外传不等于禁止本地历史。敏感原件、Diff、事件详细载荷、模型提示词、Embedding 均不允许默认上传；在全局 Ignore 与目录 Ignore 冲突时采用最严格策略。当前实现未达到该策略：全局文件与工作区内各级 `.LADONignore` 合并为同一匹配器，各级文件中的排除模式以工作区根为基准、对整个工作区生效；全局文件与根 `.LADONignore` 中的 `!` 例外不受目录范围限制，对整个工作区生效（可重新包含全局文件已排除的文件）；嵌套文件中的 `!` 例外规则仅作用于该文件所在目录及其子目录，但在该范围内可重新包含全局文件或根规则已排除的文件，包括被排除目录中的文件，且与目录排除规则的书写先后无关（详见 34 号文档第 3 节）。嵌套 `!` 例外重新包含由根目录 `add_sensitive` 规则排除的文件是否允许，是待负责人决定的开放设计问题（见 00 号文档 RSK-16）。规则文件自身的固定排除仅对名称精确为 `.LADONignore` 的文件生效，名称大小写不同的根规则文件当前不被固定排除；`.ladon` 与 `.git` 同样固定排除，二者不受 `!` 覆盖；路径中任一组件名为二者即排除，工作区位于此类上级目录下时其中全部文件被排除（已知限制）。

## 4. 数据保留与法律
根据用户授权、云服务条款、数据存储地区及保留政策执行；用户对自身数据的云端上传负责。远端删除并不能保证服务商备份立即被物理擦除，UI 应如实提示。
