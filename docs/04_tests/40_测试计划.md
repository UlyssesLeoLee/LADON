# 40. テスト計画書（UT / IT / ST / UAT）

## 1. 质量目标
用可重复执行的测试证明全部已实现功能正确；设计中功能一律标记 Not Run / Blocked，不得通过测试文档数量判定为完成。测试环境包括 Windows 11 Pro 主机、NTFS 盘、外接 USB 磁盘、网络 NAS（可选）、Google Drive 测试账户、本地模型和网络故障模拟。

## 2. 测试层级
- UT（単体テスト）：纯函数、算法、路径权限、AES、.NEMA、Diff、FileSpace Hash 冲突。
- IT（結合テスト）：Rust Engine × Turso × CAS × Policy × Provider，真实异步接口和数据库事务。
- ST（総合/システムテスト）：用户场景、延迟、资源占用、跨卷、真实云 OAuth、安全、灾备。
- UAT（受入テスト）：实际用户按原有文档治理流程签署，必须以已批准 REQ 为输入。

## 3. 入口标准
UT：`cargo fmt/check/test` 构建成功；IT：UT 无阻断缺陷、测试数据库可重建；ST：IT 通过、目标平台可执行、脚本和监控到位；UAT：P0 全部实现且 ST 已通过。

## 4. 退出标准
UT 零失败、关键模块预定覆盖率阈值（建议分支≥80%，敏感/恢复路径≥95%）在实际工具跑过并出报告；IT 严重用例零失败；ST P0 全部通过且不存在 Critical/High 未解缺陷；UAT 用户签字并存变更记录。

## 5. 测试数据与隐私
测试仅用临时目录内的虚拟 `.env`/密钥；真实授权 Token 不放源码/日志。每次测试创建新工作区；清理仅删自身临时目录。可恢复性测试须有第二份副本，故障注入不得破坏用户真实数据。

## 6. 自动化执行
```powershell
cargo fmt --all -- --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
powershell -ExecutionPolicy Bypass -File scripts/st_smoke.ps1
```
CI 定义在 `.github/workflows/rust-ci.yml`；在没有 `Cargo.lock` 的本初始包中，首轮需要 `cargo generate-lockfile` 并检查锁定版本，之后才能使用 CI 的 `--locked`。

## 7. 缺陷分级
Critical：敏感外传、不可恢复的数据损毁、无声版本丢失；High：未审批覆盖、版本冲突错误判定；Medium：索引遗漏/性能下降；Low：文案/排版。阻断项必须修复后重跑对应 UT/IT/ST。
