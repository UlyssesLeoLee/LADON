## 2. 测试层级
- UT（単体テスト）：纯函数、算法、路径权限、AES、.NEMA、Diff、FileSpace Hash 冲突。
- IT（結合テスト）：Rust Engine × Turso × CAS × Policy × Provider，真实异步接口和数据库事务。
- ST（総合/システムテスト）：用户场景、延迟、资源占用、跨卷、真实云 OAuth、安全、灾备。
- UAT（受入テスト）：实际用户按原有文档治理流程签署，必须以已批准 REQ 为输入。

## 3. 入口标准
UT：`cargo fmt/check/test` 构建成功；IT：UT 无阻断缺陷、测试数据库可重建；ST：IT 通过、目标平台可执行、脚本和监控到位；UAT：P0 全部实现且 ST 已通过。

## 4. 退出标准
UT 零失败、关键模块预定覆盖率阈值（建议分支≥80%，敏感/恢复路径≥95%）在实际工具跑过并出报告；IT 严重用例零失败；ST P0 全部通过且不存在 Critical/High 未解缺陷；UAT 用户签字并存变更记录。

## 5. 测试数据与隐私
测试仅用临时目录内的虚拟 `.env`/密钥；真实授权 Token 不放源码/日志。每次测试创建新工作区；清理仅删自身临时目录。可恢复性测试须有第二份副本，故障注入不得破坏用户真实数据。

## 6. 自动化执行
```powershell
cargo fmt --all -- --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
powershell -ExecutionPolicy Bypass -File scripts/st_smoke.ps1
```
CI 定义在 `.github/workflows/rust-ci.yml`：`core`（Linux）与 `windows-smoke`（Windows）两个作业先执行 `cargo generate-lockfile`，再以 `--locked` 运行 `cargo test --all-targets`；`core` 作业另含 `cargo fmt` 与 `cargo clippy` 检查。`ui-prototype` 是独立工作区（`ui-prototype/Cargo.toml` 含 `[workspace]`），上述命令与 CI 均不包含其集成测试 `it_slice_a`；该测试在 `ui-prototype` 目录内以 `cargo test --no-default-features --features kernel --test it_slice_a` 运行。

数据库引擎依赖在 `Cargo.toml` 中为 `turso = { version = "=0.8.3", default-features = false, features = ["mimalloc"] }`，不启用 `fts`（该特性在稳定版工具链无法编译）。`Cargo.toml` 声明 `rust-version = "1.85"`，而依赖 `notify-types` 2.3.1 声明的 `rust-version` 为 1.91，因此构建需要不低于 1.91 的稳定版 Rust。根 crate 测试以 `cargo test --release --no-fail-fast -- --test-threads 2` 运行，结果为 104 passed，0 failed；ui-prototype 的单元测试以 `cargo test --lib --no-default-features` 运行（18 passed），集成测试 `it_slice_a` 为 26 passed。执行记录见 `46_测试执行记录与缺陷.md` 第 1 节。

## 7. 缺陷分级
