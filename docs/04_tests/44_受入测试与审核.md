# 44. 受入テスト（UAT）与对抗式审核

## UAT-01 管理已批准要件
前提：用户提供已批准 REQ 文档；步骤：打开章节、绑定新任务、向 Agent 下达请求、查看受影响基本/详细设计、查看 UT/IT/ST 和审批选项；期望：无需重建整个要件、变更理由可追溯。

## UAT-02 每文件历史完整可查
前提：10 个文件、3 次稳定保存、1 次移动、1 次恢复；步骤：打开每一文件历史；期望：事件起点、操作者、旧新版本、敏感/非敏感备份位置、恢复操作明确，无法捕获的过去历史被标为未知。

## UAT-03 LADON Ignore 不外传
前提：私有目录/密钥/文档历史；步骤：界面加入忽略、启动远端 AI、Google Drive 归档、向量索引；期望：所有受控外传都拒绝，并留下本地原因记录。

## UAT-04 低空间 Worktree 管理
前提：多个 dirty/untracked Worktree、Google Drive 正常；步骤：冻结、查看可清理项、验证恢复、恢复一个 Worktree；期望：没有未备份的数据被删除，空间回收量及历史位置透明。

## UAT-05 多 FileSpace 并行
前提：3 个文档任务，其中 2 个独立、1 个共享写入目标；步骤：运行并行任务；期望：独立分析并行，冲突任务提交被阻断，任务时间线完整。

## 必须附带的评审证据
签核版本、源代码 Commit、CI、UT/IT/ST 通过记录、数据泄露监控、云端读回日志、Win11 启动基准、风险整改与未覆盖项。当前全部待验收。

## 对抗性自审要点
1. “Hash 链防篡改”不能证明对抗者无法重建整个链；应增加外部签名检查点。
2. “Gitignore 兼容”不保证所有嵌套例外策略都达到强制拒绝要求；须额外安全测试。
3. “可上传 Drive”不代表 OAuth、令牌刷新、断点续传重试和额度可用。
4. “本地文件已归档”不代表可以安全删除唯一副本；必须读回测试。
5. “DAG 并行批次”不代表多 Agent 执行器及写事务协调已完成。
6. “Turso SQLite 兼容”不代表数据库恢复协议可直接复制活动文件。
7. “目录扫描”不保证 USB 离线变化期间每一次中间保存都能重建。
8. “.NEMA Graph 子集”不能冒充正式全语法解析器。
