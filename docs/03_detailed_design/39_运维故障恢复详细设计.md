# 39. 运行、故障恢复与审计详细设计

## 1. 运行目录
工作区根 `.ladon/meta.turso` + `.ladon/cas/xx/HASH.zst`；用户原文件不在 `.ladon`。`config/default.yaml` 是可供实现者采用的配置 Schema 草案，当前 CLI 尚未自动读取 YAML。

## 2. 持久待备份日志规划
`backup_jobs(state,attempt,last_error,updated_at)` 已建表但 CLI 未启用队列。设计要求写入前生成 Job，失败指数退避并记录 last_error，进程启动恢复 `queued/retry_wait`；如果本地空间耗尽必须告警，不能静默丢未备份历史。

## 3. 故障注入矩阵
| 故障 | 预期行为 | 验证证据 |
|---|---|---|
| CAS 写中断电 | 当前版本/事件不假成功；可能有可 GC 临时对象 | 事件链与磁盘对照 |
| Turso 提交失败 | 整次 DB 事务回滚，不产生半个版本 | 版本数量断言 |
| Google 上传失败 | 本地 CAS 保留，Job 失败可恢复 | Remote 空、local 存在 |
| 上传读回 Hash 不符 | 不允许 evict，标记 corrupt | 归档未标 verified |
| AI 模型超时 | 本地 GUI/扫描/历史正常 | UI/Worker 计时 |
| `.LADONignore` 规则语法错 | 外传 Fail-closed | 网络日志为零 |
| 大规模事件监控溢出 | 显示历史捕获间隙，触发全量一致性补扫 | 日志区间对照 |
| 两 Agent 同时改一个文件 | 其中一方显示冲突，原件不遭静默覆盖 | 两份差异/审批 |

## 4. 审计追溯
FileId/VersionId/EventId/TaskId/ApprovalId/ProviderLocator/Hash/Time/Actor 一致；重要事件可导出只读 JSON/.NEMA；历史签名、时间戳可信锚需在后续版本实现。

## 5. 恢复演习
先新目录模拟恢复→验证每个历史内容 SHA→复核 Event Chain/REQ Anchor/Task 关系→再允许生产恢复；不得将不存在的远端对象误显示为“已备份”。
