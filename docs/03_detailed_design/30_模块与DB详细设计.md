# 30. ソフトウェア詳細設計書 — Rust 模块及 DB

## 1. 项目结构
`src/main.rs` CLI 命令路由；`src/engine.rs` 主业务 UseCase；`src/store.rs` Turso Repository；`src/archive.rs` CAS；`src/provider.rs` 可插拔后端；`src/policy.rs` 忽略规则；`src/diff.rs` 条款指纹；`src/crypto.rs` AES；`src/nema.rs` DAG；`src/search.rs` Grep；`src/tagging.rs` 标签；`src/workspace.rs` FileSpace。

## 2. 主数据结构
`FileRecord{id,relative_path,current_hash,version_no,sensitive,deleted}`；`VersionRecord{id,file_id,number,content_hash,byte_size,sensitive,changed_sections,actor,reason,created_at}`；`EventRecord{seq,id,file_id,version_id,kind,old_path,new_path,timestamp,actor,reason,previous_hash,current_hash,ledger_prev_hash,ledger_hash}`。

## 3. 事务
`capture` 先将文件稳定写入 CAS 后进入 DB 事务，关联 resource/version/event 同事务提交；失败保留 CAS 孤儿，等待垃圾回收。存储历史的逆向路径以版本 ID 查到 CAS/Provider Locator，不通过路径猜文件身份。删除也生成单独 event，不删除历史。

## 4. 数据库 DDL
以 `sql/001_initial.sql` 为权威。所有业务查询使用绑定参数；建立 `resources.relative_path UNIQUE`、`versions(file_id,number) UNIQUE`、`events(file_id,seq)` 索引。大规模历史最终采用分段归档并保持 Turso 热索引。

## 5. 实际限制
- 当前 FileRef 为 UUID，但外部移动会被识别为旧路径删除+新路径创建；完整 File ID/USN 关联未实现。
- 当前 DB/历史事件只保证已捕获保存版本；未捕获的编辑器每次击键不是版本。
- 复杂 Office 二进制当前存内容快照，没有提供单元格/段落级 Diff。
- Turso 同步和向量引擎尚未实现，表结构预留不代表功能完成。

## 6. 数据流
`FileStable`→`Engine.resolve`(workspace path security)→`LadonPolicy`→`CasStore.put_file`(SHA, Zstd)→`Store.find_path`→`diff.changed_sections`→`Store.append_version`(SQL Tx)→`EventRecord`。

## 7. 可恢复性
本地 CAS 对象损坏时必须报错，不能 silently substitute 当前文件；远端读取校验 Hash 不符时不得恢复；操作历史应明确保留“内容缺失但元数据存在”状态以保证审计真实性。
