# 36. Turso Schema、事务与迁移詳細設計

## 1. Schema 权威来源
`sql/001_initial.sql`；严禁不经 Migration 修改已有用户 DB。版本库增加 `schema_migrations(version,checksum,applied_at)` 并为每次升级提供升级脚本与回滚路径（未来实施）。当前 `Store::init` 每次执行 001（建表与建索引语句均带 `IF NOT EXISTS`），并在 `schema_migrations` 中尚无版本 2 时执行 002；002 只包含 `CREATE TABLE IF NOT EXISTS` 与 `CREATE INDEX IF NOT EXISTS` 语句，不写入版本记录（其中 `schema_migrations(version, applied_at)` 表尚无 checksum 列）。版本 2 记录由 `Store::init`（`src/store.rs`）在 002 全部语句执行后以 `INSERT OR IGNORE INTO schema_migrations(version,applied_at) VALUES (2,datetime('now'))` 写入；`schema_migrations` 中已有版本 2 时不再执行 002，重复 `init` 安全。`sql/003_drive_rules_control_plane.sql` 未被 Rust 代码装入或执行。数据库引擎 `turso` 以 `default-features = false, features = ["mimalloc"]` 引入，不启用 `fts`。

## 2. 数据完整性约束
`resources.relative_path` 唯一；`versions(file_id,number)` 唯一，`events.id` 唯一，`archive_objects(content_hash,provider)` 唯一；所有关联 ID 必须经过存在性校验。当前实现：关联 ID 的存在性以 `REFERENCES` 外键声明约束：`versions.file_id`、`events.file_id`、`events.version_id`、`file_tags.file_id`、`annotations.file_id` 与 `doc_tasks.file_id` 带外键；`annotations.base_version_id`、`doc_tasks.base_version_id` 与 `governance_events.file_id` 不带外键，`archive_objects` 按 `content_hash` 关联版本且无外键。`Store` 内仅在 `mark_deleted`（文件须至少存在一个版本）与 `set_task_status`（任务须存在）中显式校验；`Engine` 的 `restore_plan`、`restore` 与 `archive_version` 在入口校验版本与文件记录是否存在；`load_version` 在入口只校验版本是否存在。每次连接执行 `PRAGMA foreign_keys = ON`，外键在 Turso 上是否实际生效需实机验证。

## 3. 事务边界
新增版本 = 一次 DB Transaction，包含 `resources`、`versions`、`events`。CAS 写入先于事务，出现失败时存在可 GC 孤儿。事件账本不可回写旧历史，更新 `resources.current_hash` 只表达当前状态。`restore` 通过 `capture` 写入：恢复出的内容与未标记删除的当前记录相同时返回 `unchanged`，不产生新版本；当前记录已标记删除时，即使内容与记录中的哈希相同，也创建新版本，事件类型为 `restored`；其余情况创建新版本。`mark_deleted`（删除标记与事件）与 `set_tags`（全部标签）各为一次事务。`add_annotation`、`create_task`、`set_task_status` 先写记录，再经另一连接写入治理事件，两步不在同一事务内，两步之间失败会留下没有对应治理事件的记录（已知限制，未来合并为单事务）。

## 4. 索引规划
查询热路径：`FileRef → latest version`、`FileRef → ordered events`、`content_hash → archive objects`、`Tag → matching file ids`、`REQ anchor → edges`。后期按文件/时间分段，旧事件 Detail 进入云端，Turso 保留稀疏索引与定位游标。

## 5. Cloud Sync 不变量
初版 Local-only。后续同步时敏感路径与内容衍生字段不能自动远程复制，需要分库或分类字段加密，并根据敏感策略过滤；即使内容加密仍需评估路径名、访问模式和流量特征泄漏。

## 6. 备份一致性
备份 DB 不得直接复制一个正在写入的 SQLite/Turso 文件（可能遗漏 WAL）；生产版应采用 Turso 支持的一致性备份/Checkpoint API 或独立导出事务方案，获得完整性校验后才上传。

## 7. 查询安全与稳定性
全部入参绑定，不允许 SQL 拼接；绑定值限定为 `&str` 与 `i64`；`String` 值在绑定前经 `.as_str()` 转为 `&str`（turso 的 `IntoValue` 不接受 `&String`），布尔值存为 0/1，`created_at`、`timestamp`、`updated_at` 等时间列为 RFC 3339 字符串（`schema_migrations.applied_at` 由 SQL 函数 `datetime('now')` 写入），引号、换行、Unicode 与 SQL 元字符原样存取；查询应按 limit/cursor 限制，避免打开 100 万个事件时将历史对象一次性载入内存。`Store` 当前的 `versions`、`events` 查询与 `ladon history` 命令均未分页；生产版必须加入 cursor 分页并按需从远端懒加载 Diff。
