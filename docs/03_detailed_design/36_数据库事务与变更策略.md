# 36. Turso Schema、事务与迁移詳細設計

## 1. Schema 权威来源
`sql/001_initial.sql`；严禁不经 Migration 修改已有用户 DB。版本库增加 `schema_migrations(version,checksum,applied_at)` 并为每次升级提供升级脚本与回滚路径（未来实施）。当前 `Store::init` 每次执行 001（建表与建索引语句均带 `IF NOT EXISTS`），并在 `schema_migrations` 中尚无版本 2 时执行 002；002 只包含 `CREATE TABLE IF NOT EXISTS` 与 `CREATE INDEX IF NOT EXISTS` 语句，不写入版本记录（其中 `schema_migrations(version, applied_at)` 表尚无 checksum 列）。版本 2 记录由 `Store::init`（`src/store.rs`）在 002 全部语句执行后以 `INSERT OR IGNORE INTO schema_migrations(version,applied_at) VALUES (2,datetime('now'))` 写入；`schema_migrations` 中已有版本 2 时不再执行 002，重复 `init` 安全。`sql/003_drive_rules_control_plane.sql` 未被 Rust 代码装入或执行。数据库引擎 `turso` 以 `default-features = false, features = ["mimalloc"]` 引入，不启用 `fts`。

## 2. 数据完整性约束
`resources.relative_path` 唯一；`versions(file_id,number)` 唯一，`events.id` 唯一，`archive_objects(content_hash,provider)` 唯一；所有关联 ID 必须经过存在性校验。当前实现：关联 ID 的存在性以 `REFERENCES` 外键声明约束：`versions.file_id`、`events.file_id`、`events.version_id`、`file_tags.file_id`、`annotations.file_id` 与 `doc_tasks.file_id` 带外键；`annotations.base_version_id`、`doc_tasks.base_version_id` 与 `governance_events.file_id` 不带外键，`archive_objects` 按 `content_hash` 关联版本且无外键。`Store` 内仅在 `mark_deleted`（文件须至少存在一个版本）与 `set_task_status`（任务须存在）中显式校验；`Engine` 的 `restore_plan`、`restore` 与 `archive_version` 在入口校验版本与文件记录是否存在；`load_version` 在入口只校验版本是否存在。每次连接执行 `PRAGMA foreign_keys = ON`，外键在 Turso 上是否实际生效需实机验证。

## 3. 事务边界
新增版本 = 一次 DB Transaction，包含 `resources`、`versions`、`events`。CAS 写入先于事务，出现失败时存在可 GC 孤儿。事件账本不可回写旧历史，更新 `resources.current_hash` 只表达当前状态。`restore` 通过 `capture` 写入：恢复出的内容与未标记删除的当前记录相同时返回 `unchanged`，不产生新版本；当前记录已标记删除时，即使内容与记录中的哈希相同，也创建新版本，事件类型为 `restored`；其余情况创建新版本。`restore` 在加载历史内容之前核对现存文件的摘要（与当前记录的 `current_hash` 比较）：摘要不一致时返回 `live file changed outside ledger; scan before restore`，不改动文件、不记录事件；读取失败时返回 I/O 错误。恢复字节先写入 `.ladon/restore` 下的临时文件，该目录与工作区的被跟踪路径分离，scan、watch 与 tag-folder 跳过 `.ladon` 目录，因此恢复过程中的中间文件不被记录。替换时先将现存文件移为备份并再次核对备份摘要，不一致或读取失败时把备份移回原位置、删除临时文件、返回同一错误，不记录事件（移回失败时错误信息给出备份路径）。恢复文件以不替换既有文件的方式放入目标位置（硬链接；卷不支持硬链接时以 `create_new` 复制）。目标路径已出现文件（`AlreadyExists`）时放置失败，不记录事件，返回的错误给出目标路径；替换前存在原文件时还给出备份路径并保留备份。其他放置失败时，替换前存在原文件则以同样方式把备份放回原位置；放回失败时备份保留在 `.ladon/restore` 中，错误不给出备份路径（已知限制）。放置之后 `capture` 记录失败时，先把目标文件移为 `.ladon/restore` 下的移开文件并核对其摘要，与恢复字节的摘要比较：相等时删除移开文件，替换前存在原文件时把备份移回原位置，返回记录失败的错误；不相等（恢复字节写入之后目标文件被改动）或移开失败时，目标文件保留其内容，返回的错误同时给出目标文件路径与备份路径（替换前不存在原文件时只给出目标文件路径）。回滚途中有新文件写入目标路径时，替换前存在原文件的情况下该文件保留，返回的错误同时给出目标文件路径与备份路径。记录成功后，替换前存在原文件时删除备份；备份无法删除时恢复仍成功返回，备份文件保留在 `.ladon/restore` 中，不给出提示（已知行为）。恢复前的现存文件摘要核对、备份摘要核对与移开文件摘要核对均以 64 KiB 分块读取计算（`digest_file`），结果与整文件 SHA-256 相同。已知限制：恢复过程中把备份或移开文件移回目标路径的三处 `fs::rename`（摘要不一致时的移回、回滚时移开文件的移回、回滚后的备份移回）仍是替换语义，若在移开与移回之间有新文件出现在目标路径，该文件会被替换；回滚后的备份移回失败时，错误信息不给出备份路径；移开失败时，错误信息仍表述为目标文件已不再持有恢复字节；写入临时文件或移开目标文件失败时，临时文件保留在 `.ladon/restore` 中。`mark_deleted`（删除标记与事件）与 `set_tags`（全部标签）各为一次事务。`add_annotation`、`create_task`、`set_task_status` 先写记录，再经另一连接写入治理事件，两步不在同一事务内，两步之间失败会留下没有对应治理事件的记录（已知限制，未来合并为单事务）。

文件操作对账本的影响（ui-prototype）：删除时，Windows 构建经 `SHFileOperationW` 将文件或文件夹移入回收站，标志为 `FOF_ALLOWUNDO | FOF_NOCONFIRMATION | FOF_SILENT | FOF_WANTNUKEWARNING`：shell 自身的确认关闭，删除确认由界面在发出命令前完成；回收站无法接收某一项时，shell 在永久删除前询问用户，用户取消时调用返回 false，不删除任何内容，账本不变；用户确认时永久删除，并按下文更新账本；非 Windows 构建中 `move_to_recycle_bin` 返回 false，`delete_path` 在任何 `Store::mark_deleted` 调用之前返回删除失败（`MSG_DELETE_FAILED`），账本不变。移入回收站成功后，再对其下每个未标记删除的被跟踪文件调用 `Store::mark_deleted`；每个文件的 `resources` 行标记为已删除与追加 `deleted` 事件在同一事务中完成，已写入的事件不改写，事件链延长。回收站移动与账本更新不在同一事务内：账本更新途中失败时，文件已离开原位置而部分被跟踪文件仍未标记删除，操作返回失败（已知限制）。新建文件夹不改变账本。重命名时，若路径本身或其下存在未标记删除的被跟踪文件则拒绝，因为账本以相对路径作为键；无此类文件时重命名不改变账本。重命名时，目标名的存在检查与 `fs::rename` 之间存在竞争：`fs::rename` 替换已存在的目标，检查之后出现在目标名下的文件会被覆盖，操作仍返回已重命名（已知限制，`ui-prototype/src/app.rs` 的 `rename_path`）。

全量扫描（`Engine::scan`）的目录遍历出错时立即返回错误（`failed to scan the workspace: ...`），不标记任何文件删除；出错之前已记录的新版本保留。单个文件捕获失败（例如文件在捕获期间被改写，或被其他进程锁定）时，扫描继续处理其余文件并执行删除标记，结束时返回一个错误，列出所有捕获失败的文件路径；捕获失败的文件仍计为已见，不被标记删除。规则集未能加载时，扫描在遇到第一个将被捕获的文件时立即停止，不执行删除标记。遍历中没有可捕获的文件时，规则集不被检查，删除标记仍然执行，只标记磁盘上已不存在的被跟踪文件（已知限制）。根目录的 `.LADONignore` 在全量扫描中被跳过：若它已被记录为被跟踪文件，在其被跟踪之后的第一次全量扫描会将其标记为已删除，之后的全量扫描跳过它（已知限制）。`capture` 在判断内容未变化之前写入内容对象，因此每次扫描都会读取并压缩全部文件（已知限制）。

## 4. 索引规划
查询热路径：`FileRef → latest version`、`FileRef → ordered events`、`content_hash → archive objects`、`Tag → matching file ids`、`REQ anchor → edges`。后期按文件/时间分段，旧事件 Detail 进入云端，Turso 保留稀疏索引与定位游标。

## 5. Cloud Sync 不变量
初版 Local-only。后续同步时敏感路径与内容衍生字段不能自动远程复制，需要分库或分类字段加密，并根据敏感策略过滤；即使内容加密仍需评估路径名、访问模式和流量特征泄漏。

外存归档（`Engine::archive_version`）在以下任一情况下返回错误，不上传，也不写入归档记录：策略检查失败（错误为 `policy reload failed: all external archive transfers blocked`，直到后续重载成功为止；根规则文件缺失时即为此情况，由 `tests/it_engine.rs` 的 `tc326_missing_root_rule_file_refuses_capture_and_archive` 覆盖）；规则扫描失败（返回扫描错误）；当前文件路径被策略排除（`LADON policy denies external data transfer: <路径>`）；该版本被标记为敏感，或 `Engine::content_is_excluded` 对其内容哈希返回真（即同一内容哈希的任一版本被标记为敏感，或曾持有该内容哈希的任一被跟踪路径被当前策略排除），错误为 `sensitive version blocked from external storage`。持有路径由 `Store::paths_for_hash` 给出：对 `versions.content_hash` 相同的版本取所属 `resources.relative_path`，去重并排序，包含已标记删除的行；文件被移动后，旧路径的行（已标记删除）仍在其中。`LadonPolicy::excluded` 不规范化 `..` 组件，含 `..` 组件的相对路径，以及位于工作区根之下的绝对路径，不返回 `outside workspace`（已知限制）；归档检查的路径由账本中的相对路径拼接工作区根得到，账本路径不含 `..` 组件。同一提供方已存在该内容的归档时，取回或校验失败使调用返回错误，不上传，也不写入归档记录，本地副本也不用于修复该归档（已知限制）。

远端 AI 标签（`src/main.rs` 的 `tag-folder`）对文件发起远端端点调用前，若文件路径被当前策略排除，或其账本中的当前内容哈希使 `content_is_excluded` 为真，则跳过该调用，并输出 `skipped remote AI tagging for excluded file: <相对路径>`；回环端点（`tagging::local_endpoint`）不受此限制。tag-folder 以账本中记录的哈希判定内容，而发送给远端端点的是磁盘上当前读取的前 16 KiB 字节：被跟踪文件已被改写为排除内容但尚未被捕获时，判定仍按旧哈希进行，排除内容可被发送（已知限制）。该跳过分支没有自动化测试；`tc319_copy_of_excluded_content_is_excluded` 覆盖排除内容在其他路径副本上的 `content_is_excluded` 判定，不覆盖 tag-folder 的跳过分支。指定 `--endpoint` 与 `--model` 时，来源统一记为 `ai+rules`，即使该文件的 AI 调用被跳过（已知限制）。遍历错误被忽略，未被跟踪的文件被静默跳过（已知限制）。

## 6. 备份一致性
备份 DB 不得直接复制一个正在写入的 SQLite/Turso 文件（可能遗漏 WAL）；生产版应采用 Turso 支持的一致性备份/Checkpoint API 或独立导出事务方案，获得完整性校验后才上传。

## 7. 查询安全与稳定性
全部入参绑定，不允许 SQL 拼接；绑定值限定为 `&str` 与 `i64`；`String` 值在绑定前经 `.as_str()` 转为 `&str`（turso 的 `IntoValue` 不接受 `&String`），布尔值存为 0/1，`created_at`、`timestamp`、`updated_at` 等时间列为 RFC 3339 字符串（`schema_migrations.applied_at` 由 SQL 函数 `datetime('now')` 写入），引号、换行、Unicode 与 SQL 元字符原样存取；查询应按 limit/cursor 限制，避免打开 100 万个事件时将历史对象一次性载入内存。`Store` 当前的 `versions`、`events` 查询与 `ladon history` 命令均未分页；生产版必须加入 cursor 分页并按需从远端懒加载 Diff。
