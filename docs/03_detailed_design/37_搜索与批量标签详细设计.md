# 37. 检索、标签与向量设计

## 1. 搜索分层
Level 0 File ID/Name Index（NTFS MFT/USN, Everything 可选）；Level 1 IDE1.0 Grep 逐文件文本/Regex；Level 2 BM25F 多字段倒排；Level 3 Embedding 向量语义；Level 4 `.NEMA` Graph 关系扩大召回。结果融合建议 RRF + 可解释命中原因，保持元数据筛选与权限排除。

## 2. 标签请求
`TagRequest{directory,recursive,presets,description,model,endpoint,policy_epoch}`。预设：project, topic, IPA phase, status, technology, requirements, risk；支持用户自然语言阐述。标签应记录源模型/规则/审批/内容 Hash，生成结果先预览再批量接受。

## 3. 当前代码
CLI `tag-folder` 提供关键词规则与 OpenAI-compatible `/v1/chat/completions` 请求（需 `--endpoint`, `--model`）；默认不联外。被 `.LADONignore` 命中时禁止发送远程模型，允许用户显式请求本机 loopback 模型；现有代码不支持服务端请求队列、标签锁定、真正向量检索。

## 4. 向量存储规划
按 Document Chunk/Model 计算 SHA Key；写入 Turso 关联表，向量维度与版本必须一致，向量不作为文件内容完整备份替代物。按文件变化仅重新向量化变化块。大小受用户配额控制；冷 Embedding 可以删除后重建，敏感源不能发给远程 Embedding。

## 5. 模型安全
优先本地 Ollama。远端使用 HTTPS、白名单 host、明确用户授权；提示词只放入已授权文本片段且截断输出，防止大文件、二进制、提示注入造成无限操作链。模型返回的标签不能直接作为文件移动/删除命令，必须由规则确认。

## 6. 测试
精确关键词、跨中日英文、特殊编码、OCR 提取后、相同多 Worktree 内容去重、模型维度变更、敏感路径远程拒绝、文件变更后旧向量失效、冷索引可重建。
