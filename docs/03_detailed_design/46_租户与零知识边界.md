# 46. 詳細設計 — 多租户与隐私信任边界

## 1. 最小 Vercel 控制面

保留：`identities,tenants,workspaces,memberships,device_sessions,archive_bindings,conversations,chat_messages(密文),agent_grants`。Vercel Functions 在每次有权限的 API 请求中验证真实 OIDC 身份并从 Turso 控制面查询成员角色，绝不相信前端自行声明的 role/tenant。

## 2. 数据流矩阵

| 数据 | 本地 | Drive | Vercel / Turso Cloud |
|---|---|---|---|
| 文件原件 | 是 | 加密，仅当允许上传 | 禁止 |
| Diff / 历史正文 | 是 | 加密，仅当允许上传 | 禁止 |
| 文件路径/隐私标签 | 是 | 默认仅不透明化元数据 | 禁止 |
| 身份/租户/成员角色 | 本地会话缓存 | 非权威 | 是，服务器判定 |
| 设备公钥/撤销信息 | 是 | 可归档密文 | 是 |
| 团队聊天 | 本地明文仅被授权终端 | 加密消息段 | 仅短期密文投递队列及必要路由元数据，长久历史留在用户云盘 |
| Drive OAuth refresh token | 系统安全凭据存储 | 禁止 | 禁止 |

## 3. 无法规避的服务端要求

**多用户多租户不能通过 Google Drive 的自定义命名规则获得安全隔离。** 需要可信权限裁决、成员更改与设备撤销通道。Drive ACL 与 LADON RBAC 两套授权均需满足，不能用一个替代另一个。

## 4. 密钥治理

每个 workspace 独立数据密钥，成员设备使用封装密钥领取。加入/撤销、轮转、丢失设备、离线撤销延迟、恢复密钥/保管流程须设计和审计；当前工程**没有生产级密钥分发**，因此团队共享数据的 E2EE 目前属于待实现。

## 5. Serverless 示例

`server/vercel/` 提供 Google OIDC token 校验、成员查询、工作空间列举、密文聊天写入的基础 Route Handler。不是完整 OAuth 用户注册、授权/刷新、速率限制、设备安全和租户隔离验收品。严禁将此样例直接用于生产。
