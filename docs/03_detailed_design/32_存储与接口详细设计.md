# 32. StorageProvider / Google Drive / NAS API 詳細設計

## 1. Rust 接口（当前）
```rust
#[async_trait]
pub trait StorageProvider: Send + Sync {
    fn name(&self) -> &str;
    async fn put(&self, content_hash: &str, encrypted: &[u8]) -> Result<String>;
    async fn get(&self, provider_locator: &str) -> Result<Vec<u8>>;
    async fn delete(&self, provider_locator: &str) -> Result<()>;
}
```
`provider_locator` 是外部系统返回的地址；业务只引用 `file_ref`, `version_id`, `content_hash`，避免未来切 NAS 导致 ID 全变。

## 2. 加密对象格式
`MAGIC: 8 bytes LADONv1! | NONCE: 12 bytes random | AES-256-GCM ciphertext+tag(Zstd plaintext)`。`content_hash` 是压缩**前**明文字节的 SHA-256，上传后再读回解密并验证。密钥必须来自用户配置的安全凭据，当前从 `LADON_ARCHIVE_KEY_HEX` 环境变量读入 32 Byte 密钥。

## 3. Google Drive 流程
1. 管理员通过 OAuth 2.0 选择 Drive folder，取得最小化权限。
2. 使用 `files.create?uploadType=resumable&fields=id` 提交非敏感历史对象元数据；Drive 返回 Location 会话地址。
3. PUT 加密压缩对象；获得云端 File ID，记录 Locator。
4. 立即 GET `files/{id}?alt=media`，解密、验证明文 Hash；成功写 ArchiveObject `verified_at`。
5. 可安全释放本地历史对象前检查其他引用、是否只有一个备份源、用户保留策略；失败保持本地副本。

当前代码**实现了第 2–4 步的基本 HTTP 路径**，但还没有 OAuth PKCE UI、Refresh Token 自动刷新、长文件多 Chunk Resumable Continue、配额指数退避及生产环境实账号成功证据。超大对象受 128 MiB 读取上限限制。

## 4. NAS 和其他 Provider
本期 NAS 接口是**用户已经挂载的目录**（例如 SMB 共享盘路径），由 `FilesystemProvider` 实现读写。未来独立 `SmbProvider`, `WebDavProvider`, `S3Provider`, `OneDriveProvider` 应实现权限、限流、范围读取、断点上传以及健康检测能力，并提供 Capability Manifest。

## 5. 迁移事务
`MigrationJob{from_provider,to_provider,object_hashes,manifest_version,verified_count,state}`。迁移时先复制并读回校验，再将新 locator 加入索引，不直接覆盖旧 locator；完成全量复核后才改变主后端。失败可继续读取旧副本。删除需显式 Dry-run 与审批。

## 6. 云端日志和 Turso
Event Log 可由本地小 WAL + 压缩云端 segments 存储，Segment 每段含序号范围/哈希校验点。当前核心保留在 Turso 本地，历史 log 的云分段上传与恢复回放属于设计项，不能将本期 `archive_version` 误称作已具备全面云日志。

## 7. 敏感历史追溯
每版本存 `sensitive` 标记；访问时还需实时规则重评估。生产版增加“曾被敏感规则命中的内容哈希”与泄密溯源表，避免规则放宽时旧敏感对象外传。云端 Provider 不保存明文路径/章节文本，文件名只用 Hash。

## 8. 错误与恢复
401 token expired→保持 CAS + 待重试；403 权限不足→提示重新授权；429/5xx→指数退避 + 幂等重试；上传状态不明→通过对象名/Manifest 查重；网络断联→不宣称可恢复；解密失败→隔离对象并禁用本地清理。
