# 34. .LADONignore 安全策略详细设计

## 1. 命名与规则
用户约定文件名为 `.LADONignore`（大小写严格遵守项目规范）；界面文字“LADON Ignore”。解析采用 `ignore::gitignore::GitignoreBuilder` 风格，支持 `*`, `**`, 目录、`!` 例外、`#` 注释。第一版加载全局变量 `LADON_GLOBAL_IGNORE` 指定的文件，以及工作区各目录规则。

## 2. 命中语义
`.gitignore` 仅控制 Git 追踪，本规则控制**外部数据流**。匹配文件仍可本地查询、建立历史、编辑/恢复，默认禁止 Google Drive/NAS 外存、远端 AI 请求、远端 Embedding/日志同步等任何外传。`.LADONignore` 本身、`.ladon` 应用目录及 `.git` 内部数据强制保护，不接受 `!` 例外覆盖。

## 3. 多级优先级
强制保护集合（内部 DB/证书/密钥） > 全局管理员拒绝 > 工作区拒绝 > 子目录拒绝 > 用户明确的分类例外。生产版要求“某个子目录 `!` 例外不能取消更高层强制保护”，不得简单套用 Gitignore 后返回允许；本期代码实现的是 gitignore 匹配 + 内部目录强制排除，管理员规则优先级升级仍待实现。

## 4. 重评估与净化
规则发生变化后扫描已归档记录，发现过去泄露敏感资源时生成 `security.reclassification` 事件，显示供应商删除范围并由用户审批远端删除。不能保证平台内部备份立即物理擦除；应提示可见可控的最终状态。

## 5. 路径安全
先 OS 级 File ID/重解析点检查，之后 Canonical Path 作用域对照，杜绝 `..`、symlink、UNC/device 路径绕过。未来针对 Windows Reparse Point 与大小写不敏感路径逐项 ST。避免“检查时一个路径、上传时另一个路径”的 TOCTOU，通过已验证 FileRef/文件句柄访问。

## 6. 测试
包括嵌套文件夹、例外、强制保护、目录改名、文件移动、忽略文件自身、远端 AI、云存储、向量索引、metadata 泄露、现有云端归档回查。当前 UT 主要覆盖常规模式、越界及规则文件自身。
