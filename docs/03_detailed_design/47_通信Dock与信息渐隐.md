# 47. 詳細設計 — 底部通信 Dock / Explorer 状态信息融合

## 1. 单一底部结构

`App Shell -> Explorer Content (flex 1) -> BottomDock`。**BottomDock 是窗口最后一个可见区域**，不会多建独立传统状态栏。状态摘要居左，AI/团队会话选择位于输入前，附件/提及/发送位于右。默认一行，点击上折箭头展开历史；历史占用底部 Dock 上方的空间。

## 2. 动态渐隐规则

`status_opacity(idle_ms,critical,hovered)`：0～2300ms=1；2300～4000ms 线性渐变；超过4000ms=0。hover 与键盘 focus 使提示回显；`critical=true` 恒为1。绝不对内容丢失、敏感上传拒绝、未归档风险、租户越权、恢复失败、冲突提示执行淡出。

## 3. 消息业务

AI 和成员使用统一消息对象，但发送者、可见范围、可用命令与权限不同；发送时可附带 FileRef+版本与要件条款 ID，防止路径移动后无法追踪任务。跨终端聊天实现后支持幂等客户端消息 ID 和断线补齐，禁止直接将敏感附件外传到聊天云端。

## 4. 交互规范

- `Tab` 进入 Dock 控件，`Ctrl+Enter` 发送（允许用户更改）；Esc 返回文件列表；折叠时不丢当前草稿。
- 聊天历史不会在未经操作情况下自动展开；AI 建议只显示轻提示，不强迫打开侧栏。
- 无需聊天时 Dock 可配置极简状态/隐藏历史，但发送输入仍在下缘。

## 5. 对照代码与原型

`src/ui_layout.rs`（可测试布局规则）、`ui-v13-responsive/interactive-preview.html`（浏览器演示）与 `15~20_*.svg`（静态尺寸参考）；完整 Slint GUI 接入待做。

**Vercel 中继保留限制：** 只存最长 7 日（示例配置）的临时密文队列，不作为聊天历史权威源；必须部署过期删除任务。跨设备历史来自用户授权 Drive/NAS 的加密聊天段。
