# 33. FileSpace / DAG / Commit Coordinator 詳細設計

## 1. FileSpace 生命周期
`created → claimed → active → paused → waiting_approval → committed / aborted → released`。空间租约 `owner_agent`, `scope`, `snapshot_epoch`, `expires_at`, `resource_budget`。读取使用不可变 FileRef Snapshot；关闭时释放 Worker 但历史事件保留。

## 2. 依赖调度
.NEMA Graph Node 关联 `task_id/file_ref/requirement_anchor`，边表示 `requires/blocks`。使用 Kahn 拓扑算法建立层序，并发执行每层互不依赖任务；环直接拒绝、悬空节点和超出权限也拒绝。**无依赖不保证不冲突**，同层还需校验写入集是否交叉。

## 3. 写入集冲突检测
每 Plan 必须声明 `reads: [(file_ref,version)]`, `writes: [(file_ref,expected_hash)]`；调度前排他检查同一 FileRef 写入；在提交瞬间通过 `expected_hash` CAS；若文件被外部应用修改则丢弃本次 Commit 并要求重取 Snapshot。

## 4. 原子提交设计
生产版采用 `prepare` 写临时对象、`validate` 校验权限与当前版本、`commit` 原子替换（Win32 ReplaceFileW 语义需研究）、`journal` 记录事务、`finalize` 更新 Turso 事件。跨多个文件的真正原子性需采用恢复日志或补偿事务，不能简单宣称 OS rename 具备多文件原子性。

## 5. 资源池
IO Pool（目录枚举/Copy）、Compute Pool（Hash/Diff/Grep）、Model Pool（OCR/Embedding）、Agent Pool（FileSpace）分离。优先级：用户交互>历史捕获>同步归档>索引预热>AI 扫描。共享相同原件时只读一次并缓存引用，避免重复复制文件内容。

## 6. 工作区退出和回收
Git Worktree 冻结前取得 HEAD+Index+Uncommitted Patch+Untracked Archive+LFS 依赖+Submodule 信息；只在真实恢复演练完成后建议移除。受 `.LADONignore` 保护的内容如果无法迁至用户允许的安全介质，自动回收必须阻断。

## 7. 实施状态
`workspace.rs` 仅实现 Snapshot 与单文件 Hash 冲突守卫；CLI `parallel` 仅输出 DAG 批次。没有真实多 Agent 进程池/文件事务协调器/Worktree 归档，不应把图分批当作并行任务已执行。
