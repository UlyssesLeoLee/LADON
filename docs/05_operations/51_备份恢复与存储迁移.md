# 51. 备份恢复、Cloud Provider 运维与迁移

## 1. 存储配置约定
本地 `.ladon` 负责 Turso、CAS 和临时归档；Google Drive/NAS/S3（设计）负责加密后的冷对象。NAS 在初版是操作系统挂载卷，网络异常不可误判为逻辑文件已删除。

## 2. 归档账本
每个 `(content_hash,provider)` 有 locator、加密状态、verified_at。运营 UI 应显示 Verified / Local Only / Broken / Restoring，不得显示“上传请求已发出=已备份”。

## 3. 迁移
先冻结旧端对象写入→查询全量 Manifest→将加密对象迁往新端→逐个读回解密校验→记录新 Locator→切换默认 Provider→保留旧端至少一个回滚周期→经用户批准清理旧端。

## 4. 受保护数据
LADON Ignore 命中对象仅本地受保护备份，禁止误清理。只有用户明确选择自管私有 NAS 且重新批准规则时，才考虑迁移；规则解除也不应自动上传所有历史版本。

## 5. RTO 与一致性
Turso 当前只有本地嵌入式 Schema 与历史索引；生产版数据库整体恢复需要一致性 Snapshot 和事件重放。云端 CAS 并不能单独重建所有文件路径、任务和事件链；必须同时保存受批准的元数据恢复包。
