# 50. 环境搭建与执行操作手册

## 1. 开发环境
Windows 11 Pro，Rust stable（建议 rustup 安装）、Cargo，PowerShell 7 可选。核心代码基于 `turso = 0.8.3`，需连 crates.io 获取依赖。工程目录可以位于任意非敏感测试路径，不需要安装 Tauri/Node.js。

## 2. 基本操作
```powershell
cargo generate-lockfile
cargo fmt --all
cargo build --bin ladon
cargo test --all-targets

$root = 'D:\my-ladon-test-project'
New-Item -ItemType Directory -Force $root | Out-Null
cargo run --bin ladon -- --root $root init
Set-Content -Path (Join-Path $root 'requirements.md') -Encoding UTF8 -Value '# REQ-001'
cargo run --bin ladon -- --root $root scan
cargo run --bin ladon -- --root $root files
cargo run --bin ladon -- --root $root history requirements.md
cargo run --bin ladon -- --root $root verify requirements.md
cargo run --bin ladon -- --root $root grep 'REQ-001'
cargo run --bin ladon -- --root $root ignore-check secret.pem
cargo run --bin ladon -- --root $root tag-folder --presets 'project,stage' --description 'IPA 阶段' --recursive
```

## 3. 历史冷归档
非敏感版本先在 `history` 获取 `version_id`。设置 `LADON_ARCHIVE_KEY_HEX` 为密码学安全生成的 32 字节随机值（64 个 Hex 字符），绝不可用文档示例密钥。
```powershell
# 已经安全配置环境变量后（此处不展示真实密钥）
cargo run --bin ladon -- --root $root archive VERSION_ID --provider local --destination D:\ladon-archive
# 读回、解密、SHA 校验通过之后，方可选 --evict-local
```

## 4. Google Drive
本版仅提供试验性 REST 适配器：在外部按 OAuth 取得合法 access token，放 `LADON_GOOGLE_ACCESS_TOKEN` 环境变量，按需设置 `LADON_GOOGLE_FOLDER_ID`，再运行 `archive VERSION_ID --provider google_drive`。令牌刷新/UI 授权尚待开发；**先用单独测试账号**，禁止用真实敏感资料测试。

## 5. NAS
将 NAS 共享目录挂载到 OS 文件路径（含 NTFS/SMB 映射盘），选择 `--provider nas --destination Z:\ladon-history`。当前实现使用挂载目录，不是内建完整 SMB/WebDAV 客户端。

## 6. 恢复
`ladon plan VERSION_ID` 查看计划；`ladon restore VERSION_ID --approve` 从本地 CAS 恢复；如本地已驱逐，还要指定 `--provider local --destination ...` 或 Google 适配器。恢复前默认拒绝与已捕获的当前 Hash 不一致的活文件。

## 7. 原生 GUI 验证
`cd ui-prototype; cargo run --release` 启动 Slint；该原型仅支持后台目录读取与创建 `.LADONignore`，不应将其视为完整文件管理器/编辑器。

## 8. 运行安全
不用管理员权限运行普通文件操作。凭据、加密密钥不写入版本库；`.ladon` 目录应备份本地热数据库，外传另遵守 LADON Ignore。实验阶段以测试目录为主。
